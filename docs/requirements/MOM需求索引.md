# MOM Platform 需求索引

> 状态：M00 文档落地稿，待用户验收。本文管理稳定需求 ID、版本归属与追踪，不宣称需求已实现。版本和里程碑以[项目基线](../plans/MOM项目基线.md)为准；场景与测试证据以[V1 业务验收基线](../testing/V1业务验收基线.md)为准；当前实现见[实现地图](../当前实现地图.md)。

## 1. 编号与状态

`MOM-R-NNN` 是永久需求身份，版本和里程碑是可变属性；不得用旧 `REQ-*` 编号暗示新 V1 的范围仍等同于历史计划。需求状态为候选、评审中、已批准、实施中、待验收、已验收、延后、废弃。下列九条是已批准 M00 规划下的 **V1 需求草案**，业务实现与验收均尚未开始；切片实施前仍须评审状态、事务、契约和失败语义。

每条需求必须追到主里程碑、能力、场景和证据。`SC-*` 的操作步骤、预期事实和证据等级见[验收基线](../testing/V1业务验收基线.md)。

### 本轮用到的能力 ID

这只是 V1 需求引用的最小能力索引，不重建整个长期能力地图：`CAP-MDM-01` 工厂资源、`CAP-MDM-04` 批次制造定义、`CAP-MDM-06` 质量标准、`CAP-MDM-07` 定义发布；`CAP-WMS-01` 库存事实、`CAP-WMS-02` 受控期初、`CAP-WMS-04` 生产预占与领用；`CAP-MES-01` 工单快照、`CAP-MES-02` 批次执行；`CAP-QMS-01` 成品检验放行；`CAP-TRC-01` 正反向谱系；`CAP-IAM-01` 身份与功能授权、`CAP-PLT-03` 业务审计和观测。编号表示产品能力，不表示已有实现；现状只以[实现地图](../当前实现地图.md)为准。

## 2. V1 最小需求契约

### MOM-R-001 已发布批次制造定义

- **角色/前置**：工艺工程师；工厂、物料、计量单位和制造资源已建档。
- **正常结果**：本厂 Formula、Routing、生产版本和质量标准可校验、发布并供新业务引用；BOM 通用化不是 V1-01 前置。
- **异常/失败**：跨厂、未发布、失效或不一致引用拒绝发布/引用；不改变已发布历史修订。
- **事实 Owner/能力/里程碑**：MDM 静态定义；`CAP-MDM-01/04/06/07`；`V1-01`。
- **场景/通过/证据**：`SC-CFG-01`、`SC-E-01` 的定义部分；两产品定义正确发布、错误定义未生效；MDM 契约与 PostgreSQL 集成测试、隔离环境发布记录。

### MOM-R-002 可信期初原料

- **角色/前置**：授权仓库人员；存在真实历史资料或正式授权的迁移声明，仓库、物料和库位可用。
- **正常结果**：原料库存一次性入账，保留来源、可信质量依据、责任及审计关联；经确认的合格原料方可参与后续分配。
- **异常/失败**：无可信依据、无权、重复过账或来源冲突时不得产生新增可用量；不得伪造历史检验或以期初代替日常收货。
- **事实 Owner/能力/里程碑**：WMS 库存和期初事实；`CAP-WMS-01/02`；`V1-01`。凭据格式、审批角色和审计字段是本里程碑**开发前约束**。
- **场景/通过/证据**：`SC-BAT-01` 起点、`SC-E-01`；库存流水、余额、来源与操作记录可核对；PostgreSQL 集成测试及隔离环境人工验收。

### MOM-R-003 工单下达与定义快照

- **角色/前置**：计划员；本厂适用制造定义已发布。
- **正常结果**：MES 创建、下达工单，固化适用工厂、物料、定义修订及执行依据；旧工单不受后续发布影响。
- **异常/失败**：跨厂、未发布或不一致版本拒绝下达；失败不留下看似已下达的工单。
- **事实 Owner/能力/里程碑**：MES 工单与快照，MDM 提供定义引用；`CAP-MES-01`；`V1-02`。
- **场景/通过/证据**：`SC-CFG-02`、`SC-SEC-01`；新旧工单引用各自修订；契约与数据库集成测试、隔离环境单据核对。

### MOM-R-004 需求及库存预占

- **角色/前置**：生产主管或经授权的执行者；工单已下达，原料库存可用。
- **正常结果**：MES 的物料需求可回指工单；WMS 对满足资格的库存建立不超量预占。
- **异常/失败**：不足、待检、冻结、过期或跨厂库存不得预占；并发不得超占，结果未知时不得自动换键重试。
- **事实 Owner/能力/里程碑**：MES 物料需求，WMS 可用判定与预占；`CAP-WMS-04`；`V1-03`。批次有效期来源、计算规则和预占时过期判定是本里程碑**开发前约束**。
- **场景/通过/证据**：`SC-E-02/03`、`SC-SEC-01`；库存资格和并发余额核对；PostgreSQL 并发集成测试与隔离环境复核。

### MOM-R-005 领用与实际投料

- **角色/前置**：仓库员和操作员；工单已下达且相应原料已预占。
- **正常结果**：WMS 留领用事实，MES 留实际投料的原料批次、数量、工序、时间和操作者；领用与投料可区分。
- **异常/失败**：领而未投、重复投料、超量或处理结果未知均有可核对状态，不重复扣减或隐式制造投料事实。
- **事实 Owner/能力/里程碑**：WMS 领用/库存，MES 实际投料；`CAP-WMS-04/CAP-MES-02`；`V1-03` 领用、`V1-04` 投料。
- **场景/通过/证据**：`SC-E-04/05/06`；两域事实、库存交易与操作记录一致；集成测试和跨服务故障注入。

### MOM-R-006 产出与制造关联

- **角色/前置**：操作员；有效工单及实际投料事实已存在。
- **正常结果**：MES 形成产出批次、数量及输入→输出制造关联，带可回查源事实 ID；WMS 为待检成品建立不可用实物库存事实。
- **异常/失败**：重复回执、响应丢失或部分失败不得重复增加产出/库存，也不得丢失或猜测制造关联。
- **事实 Owner/能力/里程碑**：MES 制造关联和产出，WMS 库存，Traceability 以源事实构建谱系；`CAP-MES-02/CAP-TRC-01`；`V1-04`。
- **场景/通过/证据**：`SC-BAT-01`、`SC-E-06/09`；产出、库存和源关联逐项核对；L3/L5 故障测试及脱敏业务记录。

### MOM-R-007 检验、放行与可用状态

- **角色/前置**：质检员及质量主管；成品处于待检状态且质量标准已发布。
- **正常结果**：QMS 记录检验、判定和授权放行；WMS 只改变既有实物库存的可用状态，不重复增加数量。
- **异常/失败**：未放行成品不可分配；无权、重复放行或定义失效均不得制造第二份实物库存。
- **事实 Owner/能力/里程碑**：QMS 运行时质量事实，WMS 库存可用状态，MDM 质量定义；`CAP-QMS-01`；`V1-05`。
- **场景/通过/证据**：`SC-E-07/08`、`SC-BAT-01`；放行前后实物总量一致、可用量符合判定；集成测试、隔离环境与人工质量签收。

### MOM-R-008 正反向追溯

- **角色/前置**：质量人员；投料、产出与源关联事实已形成。
- **正常结果**：由成品定位原料来源、由原料定位受影响成品；每条关系可追到 MES/WMS 源事实。
- **异常/失败**：缺失或冲突事实时明确报告不完整，不事后猜测或静默补边。
- **事实 Owner/能力/里程碑**：Traceability 谱系与查询，MES/WMS 保留各自源事实；`CAP-TRC-01`；`V1-06`。
- **场景/通过/证据**：`SC-BAT-01`、`SC-E-09`；双向结果与源事实一致；集成测试及人工业务核对。

### MOM-R-009 V1 整体验收与工厂边界

- **角色/前置**：本厂生产、仓库、质量人员及验收负责人；`MOM-R-001～008` 已进入待验收。
- **正常结果**：浏览器贯通 D-004，双产品和跨修订配置运行；每个事实可审计，当前已使用入口在服务端校验工厂归属。
- **异常/失败**：跨厂引用、操作、查询与越权请求被拒；配置发布失败或历史变更不能污染已发生业务。CI 通过不代表业务验收通过。
- **事实 Owner/能力/里程碑**：Auth 与各业务 Owner；`CAP-IAM-01/CAP-PLT-03`；`V1-07`，工厂约束由各切片首次引入时验证。
- **场景/通过/证据**：`SC-BAT-01`、`SC-CFG-01/02`、`SC-SEC-01` 及所有 V1 发布阻断 `NFG`；L3/L5/L6 证据和人工签收齐备。

## 4. 旧非功能需求逐项适用性

原[非功能需求](非功能需求.md)未整体失效。分类：**保留/映射**表示原则继续有效并在相关 `NFG` 首次运行时验证；**后续适用**表示仍有效但触发能力不在当前 V1 范围；**V1 替代**仅限已有 Accepted ADR 明确改变的运行时要求；**重定阈值**表示不能直接继承旧 V1 的测量范围或数值，需在对应里程碑评审。`NFG` 的里程碑、回归和证据见[验收基线](../testing/V1业务验收基线.md#4-v1-非功能质量门)。

| 旧条款 | 适用性及新归属 |
|---|---|
| NFR-REL-001 | 保留/映射 `NFG-03/04`；V1 涉及的重复风险写入按业务请求键和事实去重验证，不能从框架原语推断全部写入口均已支持 |
| NFR-REL-002 | 后续适用；使用 RocketMQ 的切片必须用 Inbox 或等价去重，若 V1 实际使用消息即纳入 `NFG-02/03/04` |
| NFR-REL-003 | 保留/映射 `NFG-02/04`；跨服务长流程不依赖长时间 Seata 全局事务，具体失败语义按切片评审 |
| NFR-REL-004 | V1 保留库存交易与余额一致性于 `NFG-02`；完整离线重算和差异报告作为 V2 仓储对账交付 |
| NFR-REL-005 | 后续适用 V4 的生产级 PCS/WCS 命令；V1 模拟器若使用命令须进入 `NFG-03/04` |
| NFR-SEC-001 | 后续适用；若以后采用 OAuth2，仍禁止密码授权模式；V1 使用 [ADR-040](../adr/ADR-040-Mini-Auth与Redis-Opaque-Token认证基线.md) 的 Mini Auth |
| NFR-SEC-002 | **V1 替代**：Authorization Code + PKCE 和 Client Credentials 不作为 V1 运行时门，依据 ADR-040；未来身份平台另行评审 |
| NFR-SEC-003 | **V1 替代**：JWT/OAuth Audience/Scope 门不适用当前 Token；V1 Resource Server 的 Redis Opaque Token 与权限校验见 `NFG-05`，依据 ADR-040 |
| NFR-SEC-004 | V1 当前入口的功能权限和显式跨厂拒绝映射 `NFG-05`；完整工厂/车间/仓库/产线数据范围留 V4 |
| NFR-SEC-005 | 保留/映射 `NFG-01/05`；敏感信息不得进入日志、Trace 或消息负载 |
| NFR-SEC-006 | 后续适用 V4 对外生产级集成；V1 模拟器不宣称已达到生产外部认证边界 |
| NFR-OBS-001 | 保留/映射 `NFG-01` 于 V1 实际调用链；未使用的 MQ、设备命令等链路在首次引入时验证 |
| NFR-OBS-002 | 保留/映射 `NFG-01`；长链路须有可关联业务标识，不泄露敏感值 |
| NFR-OBS-003 | 保留/映射 `NFG-01`；指标标签禁止高基数用户 ID、Trace ID |
| NFR-OBS-004 | 保留/映射 `NFG-01`；运行环境具备日志/Trace 后验证可互相定位，不能以配置文件存在代替运行证据 |
| NFR-OBS-005 | 保留/映射 `NFG-01`；V1 关键动作使用低基数业务指标，后续收货等指标随业务引入 |
| NFR-MNT-001 | 保留；构建工具基线由工程规范/CI 验证，纳入 `NFG-07` 的版本证据，不复制工具版本表 |
| NFR-MNT-002 | 保留；新增业务不得引入 `javax.*`，由工程门禁验证 |
| NFR-MNT-003 | 保留；跨域 `*-api` 不暴露 Entity/Mapper/Repository，由契约审查和 CI 验证 |
| NFR-MNT-004 | 保留；Server 不直接依赖其他领域 Server，由工程门禁验证 |
| NFR-MNT-005 | 保留；关键依赖方向由既有架构测试或等价检查验证，不因此新增通用框架 |
| NFR-MNT-006 | 保留/映射 `NFG-07`；数据库变更仅经 Flyway，不修改已发布 Migration |
| NFR-DEP-001 | 后续发布目标；旧三节点 k3s 属旧 V1 范围，现 V1 的隔离环境与发布拓扑由 V1-07 审核，不直接继承旧规模承诺 |
| NFR-DEP-002 | 保留/映射 `NFG-04/08`；实际部署服务须有启动、存活和就绪检查 |
| NFR-DEP-003 | 保留/映射 `NFG-05/07`；配置与密钥分离，密钥不入 Git |
| NFR-DEP-004 | 保留/映射 `NFG-08`；V1 实际交付服务的应用回退须演练，三节点滚动升级规模另定 |
| NFR-DEP-005 | 保留/映射 `NFG-07/08`；迁移应为应用回退保留明确兼容窗口，不能回滚时有前进修复方案 |
| NFR-DATA-001 | 保留/映射 `NFG-02/07`；各 Owner 独立 Schema，禁止跨 Schema 业务 JOIN/写入 |
| NFR-DATA-002 | 保留/映射 `NFG-06`；技术时间 UTC，业务日期与工厂时区分离 |
| NFR-DATA-003 | 保留/映射 `NFG-02/06`；库存、谱系、审计关键事实不得物理覆盖以伪造历史 |
| NFR-DATA-004 | 保留/映射 `NFG-01/05/06`；敏感动作记录操作者、时间、来源及关联单据 |

**旧性能段落**：查询/写入 P95、三实例限流、10 万谱系边、库存 100 TPS 和复杂追溯限流均为旧 V1 数据规模与拓扑的目标，分类为**重定阈值**；V1-07 应按实际数据集和部署条件批准性能预算并留测量证据，不把旧数值无条件当作新版本已接受门槛。**旧故障恢复列表**：Redis、服务响应丢失和实际使用的消息/服务发现/部署故障映射 `NFG-04/08`；PCS/WCS 真实设备、三节点迁移和 WCS 堵塞在对应后续版本首次使用时演练。此分类是适用范围调整，不否定故障恢复原则。
