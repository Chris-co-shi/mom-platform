# MOM Platform 项目基线

> 状态：M00 三份权威文档已审核，GitHub 项目管理对象已建立；M00 尚待最终签收。本文是产品定位、版本和里程碑的唯一现行规划入口；运行时事实以[当前实现地图](../当前实现地图.md)及源码为准，不能从本规划推断能力已交付。
>
> 需求详情与旧编号映射见[需求索引](../requirements/MOM需求索引.md)，V1 场景及质量门见[业务验收基线](../testing/V1业务验收基线.md)。

## 1. 产品边界与已确认决策

MOM Platform 面向批次流程制造、离散制造和混合制造，承担制造定义的受控引用、现场执行、库存与质量协同、业务事实、追溯和运营管理。ERP 的企业经营与财务、PLM 的产品设计、APS 的高级优化、PLC/DCS 的硬实时控制及安全联锁、WCS 的设备调度分别保留其责任边界。采用 ISA-95/IEC 62264 和 ISA-88 的适用术语作为参照，不照搬标准对象。

- **D-001～003**：V1 用一个真实批次制造闭环交付；电子装配和配液—灌装—包装用于模型、数据与契约反证。连续制造单独研究。V1 保留 Mini Auth 与 Redis Opaque Token，外部集成先可用模拟器验证；生产级 ERP/PCS/WCS 接入依真实需求规划。
- **D-004**：首个闭环为“已核验原料库存 → 工单 → 分配与领用 → 投料 → 成品产出 → 检验与放行 → 可用成品库存 → 正反向追溯”。成品产出时先形成待检的不可用实物库存事实，放行只改变可用状态，不重复增加实物数量。
- **D-005**：BOM 与 Formula 保留不同业务语义。V1-01 优先复用现有批次 Formula、Routing 和 Production Version；不为未来离散制造提前实施 BOM 通用化重构。后续模型和版本引用的具体形态由对应技术方案评审。
- **D-006、D-009**：受控期初与日常质量放行是不同来源。期初质量可信依据可以是真实历史资料，也可以是正式授权的迁移声明；不得伪造历史检验记录，更不得用期初替代日常收货检验。凭据、责任和审批角色在 V1-01 切片评审确定。
- **D-007**：V1 一个工厂实际执行业务；第二工厂只在隔离环境验证定义与配置差异。V1 对实际入口做必要的服务端工厂归属校验；完整多工厂独立运营留在 V4。
- **D-008、D-010、D-011**：待检成品不可用；V1 完整运行批次样例，另两模式有可复核反证案例；旧基线保留历史与需求映射，由本文显式取代，不自动恢复两份已删除的旧计划。

相同业务语义优先复用稳定能力，工厂、产品与工艺差异优先评估受控配置。配置不是允许客户自由改写系统：每项配置须明确 Owner、作用域、校验、发布与历史引用；库存、质量、权限、审计及一致性不变量由代码保证。行业差异无法合理配置时可评审稳定扩展点；通用脚本、工作流和元数据引擎均非默认方案。

## 2. 版本路线与可宣称范围

| 版本 | 业务交付结果 | 配置验收 | 不得宣称 |
|---|---|---|---|
| V1 | 一个工厂完成 D-004 批次制造闭环；离散和混合样例完成模型、数据、契约反证 | 两产品不同已发布 Formula/路线/质量定义，及同产品跨修订的新旧执行；验证发布校验、历史引用、错误隔离、无需改核心代码及客户专属 Schema | 日常供应商收货、发运、生产级设备集成、安全的多工厂独立运营、BOM 通用化、连续制造 |
| V2 | 日常收货、来料检验、上架、仓储履约、调拨、发运、库存对账和基本质量处置 | 依据真实仓储差异决定是否交付有限分配或作业策略；须用不同业务结果及异常回归证明 | 通用规则引擎、完整 APS、完整 WCS 自动化 |
| V3 | 电子装配与配液—灌装—包装分别形成可运行样例，验证 BOM、SN、容器和段间交接 | 验证离散定义及必要的 SN、包装、段间差异；无法合理配置的特殊行为再评审扩展点 | 万能工单、万能数据模型、连续制造 |
| V4 | 根据真实需求建立生产级 ERP/PCS/WCS 协同及多工厂独立运营 | 验证跨厂作用域、策略、权限、历史版本和具体外部适配契约 | 无真实场景支撑的全能 Integration Hub 或完整 OAuth2/OIDC 平台 |
| 长期独立路线 | EAM 设备维保、EMS 能源、计划优化与高级分析、连续制造研究分别立项 | 各自真实场景和成本收益评审 | 仅因 Maven 骨架存在就宣称产品支持 |

V1 的两个可运行配置场景是 `SC-CFG-01`（同厂两产品差异）和 `SC-CFG-02`（同产品跨修订）。第二工厂的隔离定义验证不构成第二个运营工厂。版本划分只规定结果与门禁，不承诺未经人力评估的工期或主观完成百分比。

### 配置能力分类与版本责任

| 类别 | Owner 与约束 | 首次验收及后续演进 |
|---|---|---|
| A 平台参数配置 | System 或各技术 Owner；仅允许明确类型、作用域和权限的参数、Locale、受限字典与本地编码规则 | V1 复用已采用能力并做闭环回归；不宣称全局参数平台。V4 再核对跨厂运营作用域 |
| B 制造定义配置 | MDM 拥有静态主档、Formula、Routing、质量定义及其修订；执行域固化当时引用 | V1 验收 `SC-CFG-01/02`；V3 增加 BOM、SN/包装相关定义。新产品或修订不得要求客户专属 Schema |
| C 业务行为与策略配置 | 由实际业务事实 Owner 管理，限定策略输入、适用范围及失败行为 | V1 不以定义配置冒充策略配置；V2 依据真实收货/分配差异评估有限策略。无收益证据不建规则引擎 |
| D 行业扩展能力 | 只有具体差异无法合理配置时，才由领域 Owner 评审稳定契约及升级影响 | V3/V4 按真实案例验证；不承诺任意行业即插即用 |

所有正式支持的配置差异都必须验证：发布校验与权限、错误影响范围、历史业务引用、撤回或新修订替代路径、无需核心代码和客户专属 Schema，并记录性能及维护成本。配置项数量不是通用性指标。

## 3. 里程碑和依赖

M00 为规划与治理基线门，成果是：①产品和配置战略；②版本与需求追踪；③正确的业务依赖；④V1 场景、异常与质量门；⑤GitHub 与 Codex 执行规则。M00 完成仅代表上述文档经用户验收，不代表 V1 业务通过。

| ID | 前置 | 业务结果、需求及排除项 | 必需配置与验收出口 |
|---|---|---|---|
| V1-01 定义及可信原料 | M00 | MDM 发布本厂批次制造定义，WMS 建立受控可信期初；`MOM-R-001`、`MOM-R-002`。不验收尚不存在的工单，不实施日常收货 | B 类定义；期初可信来源、质量依据、授权、审计必须在开发前确定。`SC-CFG-01` 定义部分、`SC-E-01` |
| V1-02 工单与定义快照 | V1-01 | MES 创建/下达本厂工单并固化已发布定义；`MOM-R-003`。不要求此时已预占 | B 类修订引用；跨厂、未发布定义拒绝。`SC-CFG-02` 工单部分 |
| V1-03 物料需求、预占与领用 | V1-02 | MES 拥有工单需求，WMS 拥有可用判定、预占、拣配和领用事实；交付 `MOM-R-004` 和 `MOM-R-005` 的领用部分，后者主验收在 V1-04。领用不等于实际投料 | 批次有效期权威来源、计算规则、预占时过期判定是开发前阻断问题；`SC-E-02/03/04` 的领用部分 |
| V1-04 批次执行、产出与追溯源事实 | V1-03 | MES 记录实际投料、产出和输入→输出制造关联；WMS 记录库存交易；主验收 `MOM-R-005`、`MOM-R-006`，须核对 V1-03 领用事实与实际投料。不可推迟到查询切片才采集源关联 | 必要资源及偏差定义；`SC-E-04` 的投料及跨域核对、`SC-E-05/06`，重复或部分失败不得制造重复事实 |
| V1-05 成品检验与放行 | V1-04 | QMS 记录检验、判定与放行，WMS 改变既有待检库存可用状态；`MOM-R-007`。不重复增加实物 | B 类质量标准引用；`SC-E-07/08` |
| V1-06 正反向追溯查询 | V1-04、V1-05 | Traceability 以带源事实 ID 的 MES/WMS 事实构建与查询谱系；`MOM-R-008`。缺失关联须显式报告 | 不用自由脚本补边；`SC-BAT-01` 双向查询、`SC-E-09` |
| V1-07 业务与版本验收 | V1-01～06 | 浏览器运行 D-004 全链，签收权限、配置、失败恢复与质量门；`MOM-R-009`。不将 CI 等同于业务签收 | `SC-BAT-01`、`SC-CFG-01/02`、`SC-SEC-01`，全部 V1 发布阻断 NFG 均须有证据 |

V2 从 V1 的库存、质量和谱系事实延伸；V3 从经批次业务检验的共同契约延伸；V4 的外部集成及多工厂运营须基于真实消费者。EAM、EMS、计划优化和连续制造各有独立研究/交付门，不自动进入 V1。

后续版本只冻结业务结果与验收出口，实施需求和开发 Issue 待对应版本临近时细化：

| ID | 前置与业务结果 | 最低验收出口 |
|---|---|---|
| V2-01 日常收货与来料检验 | V1-07；供应商到货、实收、待检、检验、上架 | 收货不自动合格；短收、重复通知和拒收可核对 |
| V2-02 仓储履约与对账 | V2-01；调拨、拣货、发运、库存重算和影响分析 | 发运追到客户和原料；差异报告可定位且纠错不覆盖原事实 |
| V3-01 电子装配 | V1-07 的共同契约及 `SC-DIS-01` 反证；BOM、SN、逐工序执行 | 组件批次/SN 至整机 SN 可追溯，错件/返修可验证 |
| V3-02 混合制造 | V3-01 及批次执行；配液、灌装、包装段间交接 | 批次、容器、包装身份连续，数量守恒，错标/损耗可验证 |
| V4-01 生产级协同 | 稳定业务契约和真实外部需求；ERP/PCS/WCS 适配与对账 | 重复、乱序、超时、断线恢复经真实接入环境验证 |
| V4-02 多工厂独立运营 | V1 显式工厂归属经验及完整安全方案；数据范围与集团运营 | URL、批量、导出及异步入口跨厂越权均被服务端拒绝 |
| L1-01、L2-01、L3-01、L4-01 | 分别为设备维保、能源、计划优化/分析、连续制造研究；各需真实案例和独立立项 | 专业能力须有自身业务闭环；L4 研究只产出可行性结论，不宣称连续制造已支持 |

### 事实 Owner 与开发前评审

- MDM 是资源、物料及已发布制造/质量定义的静态权威；MES 是工单、实际投料、产出及其制造关联的事实权威；WMS 是预占、领用、库存交易与余额的事实权威；QMS 是检验、判定和放行的事实权威；Traceability 保存可回溯到源事实的谱系/查询，不通过猜测重建关联。遵循 [ADR-044](../adr/ADR-044-MDM静态主数据与WMS-MES运行时所有权边界.md)和 [ADR-045](../adr/ADR-045-MDM质量基础定义与QMS运行时边界.md)。
- V1-04 的关联契约至少可定位工单、执行批次、工序、输入批次、输出批次、数量/单位及源事实 ID；具体调用、事务、重试与纠错方式由该切片技术评审，不在 M00 预设。
- V1 在已使用入口逐项验证工厂归属和服务端跨厂拒绝；归属缺失不得默认为可跨厂。完整数据范围体系留在 V4，不提前建立 ABAC 或通用数据权限引擎。

## 4. GitHub、变更与进度治理

产品目标 → 能力 → [需求](../requirements/MOM需求索引.md) → 里程碑 → 切片 Issue → PR → [测试证据](../testing/V1业务验收基线.md) → 版本签收。`mom-platform` 的 GitHub Milestone 作为项目级跟踪入口；跨仓的 `mom-web` Issue 与平台跟踪 Issue 互链。GitHub 数量和关闭率不等于业务完成度。

- 需求状态：候选、评审中、已批准、实施中、待验收、已验收、延后、废弃。未批准需求只进入 Backlog，不自动进入当前里程碑。
- Issue 必须写需求 ID、场景 ID、范围与排除项、Owner、依赖、异常结果和证据目标；PR 关联实现 Issue，列实际验证与未执行项。实现 Issue 可随代码验证关闭，业务验收 Issue 等真实运行和人工签收后才关闭。
- 每次只细化最近一个准备实施的里程碑；下一里程碑保持依赖和验收级细度；其余保持产品结果级。进度报告分别列“源码实现、自动测试、真实环境、人工业务验收”，不得使用主观完成百分比。
- 风险记录触发信号、影响、Owner、缓解动作与解除证据；每个里程碑复盘未通过场景、配置复用效果和遗留债务。新需求先评估对当前门禁的影响，由用户决定置换、延后或变更。Agent 不得自行扩大范围。
- Codex 实施已批准切片前必须阅读相关规则、源码与需求，说明改动边界和验证。对领域 Owner、状态机、事务、失败语义、API 或安全边界的争议用 `DESIGN ISSUE` 暂停相关切片，提交选项与证据给用户；可继续不依赖争议的工作。

M00 文档审核及 [GitHub Milestone 初始化](https://github.com/Chris-co-shi/mom-platform/milestones)已完成；[M00 最终签收 Issue](https://github.com/Chris-co-shi/mom-platform/issues/51)在用户签收前保持开放，且不以此启动 V1-01 业务开发。[V1-01 平台 Issue](https://github.com/Chris-co-shi/mom-platform/issues/52)与 [mom-web 前端 Issue](https://github.com/Chris-co-shi/mom-web/issues/27)双向关联；平台 Issue 关闭不代表前端交付或业务验收通过。
