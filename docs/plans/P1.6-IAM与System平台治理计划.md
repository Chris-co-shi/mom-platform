# P1.6 IAM 与 System 平台治理计划

- Head：`phase/p1.6-system-platform`
- Base：`main`
- S00 基线 SHA：`5562e5ec1c4340dc2de0c5c80f54135df2ae6454`
- 当前阶段：里程碑 B，S06 `In Progress / Evidence Gap`；S07 `Not Started`

## 1. 目标与边界

P1.6 先建立可信工程与规范基线，再基于真实调用方证据收敛 IAM，最后建设 System Platform MVP。S00 只处理安全默认值、自动门禁、规范缺口和阶段治理；不重构 IAM，不创建 `mom-system-platform`，不冻结 IAM/System/MDM 最终领域边界。

阶段约束：

1. 每个 Slice 独立提交、验证、Review，完成后停止，不自动进入下一 Slice。
2. S01～S05 不提前实现 System 业务。
3. S06 前不得开始 IAM 大规模重构；S07 未批准前不得删除或合并认证协议入口。
4. S10 未完成前不得开始 System Server。
5. S11 必须明确 Warehouse 归 WMS、设备台账归 EAM，并裁决 IAM、System、MDM 的权威数据边界。
6. S15 没有真实动态国际化资源调用方时直接推迟。
7. Spring Authorization Server 官方 JDBC Store 和 P1.5 安全能力不因技术栈统一而重写。

| Slice | 名称 | 主要交付 | 进入下一 Slice 的门禁 |
|---|---|---|---|
| S00 | 可信分支基线、安全配置隔离、规范缺口清单、阶段治理 | 环境中立默认值、安全门禁、轮换清单、本计划与进度 | 最新 Head 必需 CI 通过；轮换未确认时不得标记 Completed、进入 S01 或合并 |

| S02 | 数据库、SQL、Repository、事务、审计、并发和数据生命周期规范 | 数据规范、事务选择树、并发/审计验收矩阵 | 不重写官方 JDBC Store，不新增业务 Schema |

## 3. 依赖与决策门禁

主路径为 `S00 → S01 → … → S10 → S11 → … → S19`，不存在反向依赖。S02 的事务规范、S03 的安全规范和 S04 的测试门禁可以互相引用已冻结结论，但不得要求后续 Slice 的生产实现作为自身完成条件。

必须由 Chris 明确批准的决策包括：认证双通道 ADR、任何 IAM 端点/Adapter 删除、IAM Admin 职责迁移、System 模块形态、数据权威边界、动态国际化是否实施、Git 历史清理、外部凭据轮换关闭以及阶段 PR 转 Ready/合并。

## 4. S00 提交与状态语义

S00 最多两个提交：安全配置/门禁/测试一个提交，计划/进度/安全记录/索引一个提交。代码清理、Commit、Push 和 CI 不等待外部轮换；轮换未确认时状态只能是 `Awaiting Credential Rotation`，Draft PR 必须保持 Draft，S00 不得标记 `Completed`，不得进入 S01。
