# P1.5：认证与授权设计基线（Mini Auth V1）

- 状态：**Current / Mini Auth V1**
- 生效日期：2026-09-03
- 权威仓库：`mom-platform`
- 当前事实来源：`fix/mini-auth`
- 架构决策：[ADR-040：Mini Auth 与 Redis Opaque Token 认证基线](../adr/ADR-040-Mini-Auth与Redis-Opaque-Token认证基线.md)

> 本文定义 MOM 第一版认证与授权的当前基线。旧 P1.5/P1.6 中关于 Spring Authorization Server、JWT、Refresh Token、OIDC、Session、Factory/Party Scope 的方案保留历史价值，但不再作为 Mini Auth V1 的运行时权威。

## 1. 阶段定位

当前目标不是建设完整 IAM 平台，而是先形成最小、清晰、可掌控的认证授权闭环：

```text
User → Role → Permission → Login → Token → Gateway → Business Service → @PreAuthorize
```

当前实施状态：

- `mom-core` CurrentActor 抽象已收敛；
- `mom-security` Opaque Token / Redis TokenStore / Resource Server 基础链已完成；
- `mom-auth` 用户、角色、权限、登录、Token 签发和 Logout 是下一阶段；
- JWT、Refresh、Session、OAuth2/OIDC 不进入当前第一版。

第一版原则：**先让业务闭环稳定运行，再依据真实需求演进协议复杂度。**

## 2. V1 权威边界

| 能力 | 当前权威模块 |
|---|---|
| 用户、角色、权限、密码认证、登录、Token 签发、Logout | `mom-auth` |
| Token 安全模型、TokenStore、Opaque Token introspection、Resource Server 基线 | `mom-security` |
| CurrentActor 抽象 | `mom-core` |
| MyBatis-Plus 审计填充 | `mom-data` |
| 最终业务授权、对象归属、领域状态 | 各业务服务 |
| 路由、CORS、限流、Correlation ID、Bearer 转发 | Gateway |

跨模块不得越过上述边界直接访问对方 Repository 或内部实体。

## 3. 用户、角色与权限

V1 采用最小 RBAC：

```text
User
  ↓
Role
  ↓
Permission
```

规则：

1. 一个用户可以拥有多个角色；
2. 一个角色可以拥有多个权限；
3. 有效权限为用户全部有效角色权限的并集；
4. Permission Code 使用稳定业务编码，例如 `mes:work-order:create`；
5. Role authority 使用 `ROLE_` 前缀，例如 `ROLE_ADMIN`；
6. Token 中只保存认证运行时需要的扁平 `authorities`；
7. 业务服务仍负责领域级最终授权，不把所有业务判断集中到 Auth。

例如：

```text
ROLE_OPERATOR
mes:work-order:create
wms:inventory:adjust
```

V1 不建设角色继承、Deny、ABAC、Factory/Party Scope 通用框架。

## 4. 登录与 Token 签发

登录流程：

```text
username + password
        ↓
mom-auth 校验账号与密码
        ↓
加载角色与权限
        ↓
生成高熵 Opaque Token
        ↓
构造 MomTokenPrincipal
        ↓
MomTokenStore.store(token, principal)
        ↓
返回 raw token
```

推荐 Opaque Token：

- `SecureRandom`；
- 32 字节随机数；
- Base64 URL Safe；
- 不编码业务信息；
- 不从 userId、时间戳等字段推导。

客户端调用受保护 API：

```http
Authorization: Bearer <opaque-token>
```

## 5. Token Principal

V1 统一认证快照：

```text
MomTokenPrincipal
├── userId
├── authorities
└── expiresAt
```

约束：

- `userId` 非空；
- `authorities` 不可变，允许为空；
- `expiresAt` 非空；
- 不加入 username、displayName、email、mobile、Factory、Party、Client、Session 等当前无必要字段。

最重要的 Spring Security 契约：

```text
Authentication#getName() == MomTokenPrincipal.userId
```

审计链依赖这个契约获取稳定用户标识。

## 6. Token Store

`MomTokenStore` 只定义逻辑存取契约：

```text
store(token, principal)
find(token)
remove(token)
```

接口不暴露 Redis Key、SHA-256、JSON、TTL 等实现细节。

默认实现为 `RedisMomTokenStore`。

### 6.1 Token Fingerprint

公共规则：

```text
raw token
    ↓
MomTokenFingerprint.of(token)
    ↓
SHA-256 lowercase hex
```

Fingerprint 用于避免在存储后端暴露原始 Bearer Credential。

### 6.2 Redis Key

默认 Redis Key：

```text
mom:token:{fingerprint}
```

Key 规则属于 Redis 实现，不属于 `MomTokenStore` 接口。

### 6.3 Redis Value

Redis Value 使用 `MomTokenPrincipal` JSON：

```json
{
  "userId": "10001",
  "authorities": [
    "ROLE_ADMIN",
    "mes:work-order:create"
  ],
  "expiresAt": "2026-09-03T10:30:00Z"
}
```

使用 Jackson 3 `JsonMapper`。

### 6.4 TTL

写入时计算：

```text
ttl = expiresAt - Clock.instant()
```

要求：

1. `ttl <= 0` 时拒绝写入；
2. Redis SET 必须一次携带 TTL；
3. 不采用先 SET 再 EXPIRE；
4. Redis TTL 是物理生命周期，`expiresAt` 是安全有效期，两者语义不同。

## 7. Resource Server

Servlet 业务服务通过 `mom-security` 提供默认 Resource Server 基线。

开启条件：

```yaml
mom:
  security:
    resource-server:
      enabled: true
```

默认行为：

- `SessionCreationPolicy.STATELESS`；
- CSRF disabled（Bearer API）；
- `/actuator/health/**` 和 `/error` 默认公开；
- 其他请求必须认证；
- 使用 Opaque Token；
- 开启方法级安全；
- 业务服务可以通过自定义 `SecurityFilterChain` 覆盖默认链。

Resource Server 开启后，如果认证基础设施缺失，应启动失败，不得静默降级成无安全链应用。

## 8. Opaque Token Introspection

认证链：

```text
BearerTokenAuthenticationFilter
        ↓
OpaqueTokenAuthenticationProvider
        ↓
MomOpaqueTokenIntrospector
        ↓
MomTokenStore.find(token)
        ↓
MomTokenPrincipal
        ↓
expiresAt 校验
        ↓
SimpleGrantedAuthority
        ↓
DefaultOAuth2AuthenticatedPrincipal
        ↓
BearerTokenAuthentication
        ↓
SecurityContextHolder
```

`MomOpaqueTokenIntrospector` 只负责认证适配，不访问 Redis API、不查询 User/Role/Permission Repository。

Principal attributes 第一版只需要：

- `sub = userId`
- `exp = expiresAt`

权限通过 `GrantedAuthority` 传递，不在 attributes 中重复保存。

## 9. Gateway 与业务服务边界

Gateway 默认：

- 原样转发 Bearer Token；
- 负责路由、CORS、限流和 Correlation ID；
- 不作为唯一认证点；
- 不承担最终业务授权。

业务服务：

- 自己作为 Resource Server 校验 Token；
- 使用 `@PreAuthorize` 完成权限校验；
- 负责对象归属、组织边界、业务状态等领域判断。

默认不在 Gateway 与后端业务服务中重复执行两次 Redis Token 查询。

## 10. Logout 与即时失效

V1 不建设 Session/Refresh 子系统。

Logout：

```text
POST /auth/logout
        ↓
读取当前 raw Bearer Token
        ↓
MomTokenStore.remove(token)
        ↓
Redis 记录删除
        ↓
后续请求立即无效
```

删除应具备幂等语义。

## 11. 失败语义

Token Store 是认证权威状态，不是普通 Cache。

必须严格区分：

```text
find(token) 找不到
→ Optional.empty()
→ invalid token
→ 401
```

和：

```text
Redis timeout / connection failure
JSON corruption
serialization failure
→ 基础设施异常继续向上传播
```

禁止：

```text
catch Exception
→ Optional.empty()
```

Redis 不可用时受保护 API 必须 Fail Closed。

具体基础设施异常最终映射 401 还是 5xx，在统一错误模型阶段决定。

## 12. CurrentActor 与数据审计

当前链路：

```text
SecurityContextHolder
        ↓
SecurityCurrentActorProvider
        ↓
CurrentActorProvider
        ↓
AuditActor
        ↓
MomMetaObjectHandler
```

`SecurityCurrentActorProvider`：

- 无 Authentication、未认证或 Anonymous 时返回 empty；
- 有效认证时读取 `Authentication#getName()`；
- 创建 `AuditActor(userId, USER)`。

因此 Resource Server 必须始终保证 `Authentication#getName()` 为稳定 `userId`。

## 13. 自动配置边界

`mom-security` 当前主要自动配置：

```text
MomSecurityActorAutoConfiguration
MomSecurityTokenAutoConfiguration
MomServletResourceServerAutoConfiguration
```

职责：

### Actor AutoConfiguration

默认提供 `CurrentActorProvider` 的 Spring Security 适配实现，并允许应用覆盖。

### Token AutoConfiguration

在 Redis 与 Jackson 基础设施存在时默认提供 `RedisMomTokenStore`，允许应用提供其他 `MomTokenStore` 实现。

### Servlet Resource Server AutoConfiguration

在显式启用 Resource Server 时：

- 默认提供 `MomOpaqueTokenIntrospector`；
- 默认提供 Servlet `SecurityFilterChain`；
- 在应用已提供对应 Bean 时退让；
- 排在 Spring Boot 默认 Servlet Security 自动配置之前，避免默认 formLogin/httpBasic 链抢先创建。

## 14. V1 明确排除

当前不建设：

- Spring Authorization Server；
- JWT；
- JWK；
- Issuer / Audience；
- Refresh Token；
- Session；
- Refresh Rotation；
- JWT Blacklist / revoked sid；
- OAuth Client CRUD；
- Authorization Code / PKCE；
- OIDC；
- client_credentials；
- SSO；
- 外部身份绑定；
- Factory / Party Scope 通用安全框架；
- 安全审计平台。

未来出现真实需求时，通过新的 ADR 重新评估。

## 15. 第一轮验收基线

`mom-security` 集成测试至少验证：

```text
有效 Token + 有权限        → 200
无 Token                   → 401
不存在 Token               → 401
过期 Token                 → 401
有效 Token + 无权限        → 403
public path                → 200
Authentication#getName()   → userId
```

`mom-auth` 完成后再增加端到端闭环：

```text
login
→ Token Store 写入
→ 业务 Resource Server 认证
→ @PreAuthorize
→ logout
→ 同一 Token 再请求返回 401
```

## 16. 演进原则

第一版优先保证：

1. 代码量小；
2. 依赖边界清楚；
3. 每一个 Bean 和调用链都能解释；
4. 安全失败语义明确；
5. 不为尚不存在的协议需求提前建设复杂基础设施。

当第三方开放平台、标准 OAuth2/OIDC 互操作、多组织 SSO、Mobile PKCE 或大规模跨地域认证成为真实需求时，再通过 ADR 演进。
