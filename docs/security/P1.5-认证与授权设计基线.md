## 1. V1 闭环

```text
User → Role → Permission
        ↓
username/password
        ↓
Spring Security AuthenticationManager
        ↓
Redis-backed Opaque Token
        ↓
Gateway Bearer 边缘检查
        ↓
Resource Server 独立认证
        ↓
@PreAuthorize
```

V1 不引入 Spring Authorization Server、JWT、Refresh Token、Session、OAuth Client CRUD、OIDC/SSO。

## 2. 用户名密码认证：优先使用 Spring Security 原生能力

Mini Auth 不再自行实现“查用户 → PasswordEncoder.matches → enabled 判断”的认证引擎。

认证链固定为：

```text
AuthenticationApplication
        ↓ AuthenticationManager.authenticate
ProviderManager
        ↓
DaoAuthenticationProvider
        ├── AuthUserDetailsService
        │      ├── UserMapper
        │      └── AuthenticationQueryMapper
        └── PasswordEncoder
        ↓
AuthUserPrincipal
        ↓
Authentication
```

职责边界：

- `UserDetailsService` 只加载账号、密码摘要、enabled 和 authorities，不负责认证；
- `DaoAuthenticationProvider` 负责密码比对和账号状态检查；
- `ProviderManager` 负责 Provider 编排并在成功后清理凭据；
- `AuthenticationApplication` 只负责调用 `AuthenticationManager`、映射稳定错误语义、签发 MOM Opaque Token；
- `UserEntity` **不得**实现 `UserDetails`，数据库模型和 Security Principal 分离。

`AuthUserPrincipal` 中：

```text
userId   = MOM 稳定身份
username = 登录凭据名称
```

V1 只真实实现 `enabled`。账号过期、账号锁定、密码过期均暂不建模，对应 `UserDetails` 状态明确返回 true，并通过注释标记为 V1 边界。

## 3. 密码

密码摘要继续使用：

```text
DelegatingPasswordEncoder
└── bcrypt cost 12
```

数据库格式：

```text
{bcrypt}$2...
```

密码不得 Trim、大小写转换、写入日志/Response/Token。只有 username 在进入 AuthenticationManager 前执行 `strip + lowercase(Locale.ROOT)`。

## 4. MOM Opaque Token 与 Spring Security 的边界

Spring Security 只解决 Credential Authentication；MOM Token 仍保持自定义设计：

```text
authenticated AuthUserPrincipal
        ↓
userId + role/permission authorities
        ↓
32 byte SecureRandom
        ↓
Base64URL without padding
        ↓
MomTokenPrincipal(userId, authorities, expiresAt)
        ↓
MomTokenStore.store
        ↓
Redis
```

Redis：

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

下游稳定契约仍为：

```text
Authentication#getName() == userId
```

Spring Security 7 的密码认证链不会替代 `MomTokenStore`、`MomOpaqueTokenIntrospector` 或 Resource Server 的 Opaque Token 验证。

## 5. Gateway 与 Resource Server

Gateway：

- 清理客户端 `X-MOM-*`；
- 受保护路由检查 Bearer Header 基本形态；
- 原样转发 Authorization；
- 不查询 Redis、不展开身份、不做最终业务授权。

Resource Server：

```text
BearerTokenAuthenticationFilter
→ OpaqueTokenAuthenticationProvider
→ MomOpaqueTokenIntrospector
→ MomTokenStore.find
→ Authentication
→ @PreAuthorize
```

## 6. Logout

`POST /auth/logout` 不是 public path。Auth Server 先认证当前 Bearer，再删除当前 Token：

```text
MomTokenStore.remove(rawToken)
```

V1 只注销当前 Token，不建设 Session 列表、Refresh Token 或“全部设备下线”。

## 7. HTTP 统一返回

Mini Auth Controller 正常与业务异常响应统一使用：

```text
mom-webmvc Result<T>
├── code
├── message
└── data
```

成功：

```json
{"code":"0","message":"success","data":{}}
```

原则：

- `Result<T>` 只属于 HTTP/API 边界；
- Application 不返回 `Result`；
- HTTP 状态码继续表达协议语义，不允许为了统一 Result 把所有错误改成 200；
- `code` 是调用方可依赖的机器契约；`message` 是展示文本；
- `messageKey` 只做未来 i18n 预留，V1 不启用 MessageSource/Locale 转换。

典型 HTTP 状态：

```text
invalid credentials                  → 401
account disabled                     → 403
resource not found                   → 404
unique/reference/version conflict    → 409
authentication/token store unavailable → 503
```

Bean Validation 错误也使用 Result，字段错误列表放在 `data`。

## 8. 分页统一

User/Role/Permission 列表统一使用 Core：

```text
mom-core PageResult<T>
├── records
├── pageNo
├── pageSize
├── total
└── totalPages
```

HTTP 参数：

```text
pageNo   默认 1，最小 1
pageSize 默认 50，范围 1..200
```

Mapper 内部仍允许使用 PostgreSQL `LIMIT/OFFSET`，但 offset 只是持久化实现细节。Application 负责 `pageNo/pageSize → offset`，不再创建只复制字段的 `PageView` / `OffsetPageResponse`。

## 9. RBAC

```text
User → auth_user_role → Role → auth_role_permission → Permission
```

Authority：

```text
ROLE_<role.code>
permission.code
```

角色名不具有隐式超级权限；管理 API 继续通过稳定 Permission Code + `@PreAuthorize` 授权。

## 10. 已知 V1 边界

Token 保存登录时 authority 快照。用户停用、角色变化或 Permission 变化不会主动重写已经签发的 Token；当前 Token 直到 Logout 或 TTL 到期才失效。

如果未来明确要求撤权立即作用于全部 Token，再增加用户级撤销/索引能力，而不是提前建设完整 Session 子系统。
