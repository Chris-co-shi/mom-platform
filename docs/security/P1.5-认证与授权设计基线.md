# P1.5：认证与授权设计基线（Mini Auth V1）

- 状态：**Current / Mini Auth V1**
- 当前事实来源：`fix/mini-auth`
- 认证决策：[ADR-040](../adr/ADR-040-Mini-Auth与Redis-Opaque-Token认证基线.md)
- 分层决策：[ADR-042](../adr/ADR-042-MOM渐进式分层与对象模型.md)
- 数据模型：[Mini Auth 数据库与代码分层](../architecture/Mini-Auth数据库与代码分层.md)

## 1. V1 已形成的闭环

```text
User → Role → Permission
        ↓
username/password Login
        ↓
Redis-backed Opaque Token
        ↓
Gateway Bearer 边缘检查
        ↓
Resource Server 独立认证
        ↓
@PreAuthorize
        ↓
Logout 删除当前 Token
```

当前实现包括：

- User / Role / Permission 管理；
- User-Role、Role-Permission 关系维护；
- BCrypt cost 12 密码摘要，使用 `{bcrypt}` DelegatingPasswordEncoder 格式；
- 登录、authority 聚合、Opaque Token 签发；
- Redis TokenStore；
- 当前 Token Logout；
- Auth 管理接口显式 Permission 授权；
- ProblemDetail 业务错误与 Bean Validation；
- MOM 内部 OpenFeign 原始 Bearer 传播。

## 2. 模块边界

| 能力 | 权威模块 |
|---|---|
| User / Role / Permission、密码认证、Login、Logout | `mom-auth-platform/mom-auth-server` |
| TokenStore、Opaque introspection、Resource Server | `mom-security` |
| CurrentActor、ErrorCode 纯 Java 契约 | `mom-core` |
| MyBatis-Plus 审计、乐观锁 | `mom-data` |
| Bearer 边缘检查、Header 清洗、路由、限流 | `mom-gateway` |
| MOM 内部同步 RPC、Correlation ID / Bearer 传播 | `mom-openfeign` |
| 最终业务授权 | 各业务服务 |

## 3. RBAC 与管理权限

```text
User → auth_user_role → Role → auth_role_permission → Permission
```

运行时 authority：

```text
Role PLATFORM_ADMIN
→ ROLE_PLATFORM_ADMIN

Permission auth:user:read
→ auth:user:read
```

角色名不具有隐式超级权限。平台管理员的管理权限由 `V3__seed_auth_management_permissions.sql` 显式授予：

```text
auth:user:read
auth:user:write
auth:role:read
auth:role:write
auth:permission:read
auth:permission:write
```

## 4. Login

外部入口：

```text
POST /auth/login
Gateway StripPrefix=1
POST /login
```

流程：

```text
username trim + lowercase(Locale.ROOT)
        ↓
加载 auth_user
        ↓
PasswordEncoder.matches
        ↓
enabled 检查
        ↓
AuthenticationQueryMapper JOIN Role / Permission
        ↓
32 byte SecureRandom + Base64URL without padding
        ↓
MomTokenPrincipal(userId, authorities, expiresAt)
        ↓
MomTokenStore.store
        ↓
LoginResponse
```

密码和 Token 不做 Trim、大小写转换或 Unicode 归一化。

默认 Access Token TTL 为 8 小时，可由 `MOM_AUTH_ACCESS_TOKEN_TTL` 覆盖。

Redis 写入失败时 Login Fail Closed，不向客户端返回不可用 Token。

## 5. Token Principal / Store

```text
MomTokenPrincipal
├── userId
├── authorities
└── expiresAt
```

Redis：

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

稳定契约：

```text
Authentication#getName() == userId
```

Token Store 是认证权威状态，不是普通 Cache。

## 6. Gateway 与 Resource Server

Gateway 只做 Credential 边缘检查：

- 清除客户端 `X-MOM-*`；
- 受保护路由要求且只允许一个合法 Bearer Header；
- 原样转发 Authorization；
- 不查 Redis；
- 不解析 User/Role/Permission；
- 不承担最终业务授权。

真实认证发生在 Resource Server：

```text
BearerTokenAuthenticationFilter
→ OpaqueTokenAuthenticationProvider
→ MomOpaqueTokenIntrospector
→ MomTokenStore.find
→ GrantedAuthority
→ SecurityContext
→ @PreAuthorize
```

## 7. Logout

外部：

```text
POST /auth/logout
Authorization: Bearer <opaque-token>
```

内部 `/logout` **不是 public path**。Auth Resource Server 先认证 Token，再由 Controller 从 `BearerTokenAuthentication` 获取已经验证的原始 Token：

```text
MomTokenStore.remove(rawToken)
→ Redis record deleted
→ 同一 Token 后续认证失败
```

Logout 只注销当前 Token。V1 不建设 Session 列表、Refresh Token 或“注销用户全部设备”能力。

## 8. Auth 管理 API

Gateway 外部路径统一为 `/auth/**`，转发到 Auth Server 时移除 `/auth` 前缀。

主要资源：

```text
/users
/roles
/permissions
```

User 支持创建、读取、分页、修改展示信息/启停、重置密码、删除、读取和替换角色关系。

Role 支持创建、读取、分页、修改、删除、读取和替换 Permission 关系。

Permission 支持创建、读取、分页、修改和删除。

删除不做隐藏级联：仍被关系表引用时返回 409，调用方必须先显式解除关系。

列表使用 `limit/offset`：默认 50，最大 200，非法参数返回 400，并使用稳定业务字段 + String ID 排序。

## 9. 错误与国际化预留

普通 Auth 业务错误使用 Spring `ProblemDetail`，稳定机器字段为 `code`。

`mom-core.ErrorCode`：

```text
code
messageKey
defaultMessage
```

V1 只使用 `defaultMessage`。`messageKey` 仅为未来国际化预留，不启用 MessageSource/Locale 消息解析。

典型状态：

```text
invalid credentials      → 401
account disabled         → 403
resource not found       → 404
unique/reference/version → 409
token store unavailable  → 503
```

## 10. 服务间 Bearer 传播

`mom-openfeign` 只用于 MOM 内部同步 RPC，全局传播：

- `X-Correlation-Id`；
- 当前 Servlet 请求中的原始 Bearer Authorization。

Feign 不解析、不验证 Token，不查询 Redis；没有当前 Servlet 请求时不生成 Authorization。

SAP、LIMS、PCS、AGV 等外部系统不得复用 `mom-openfeign`。

## 11. V1 已知边界

Token 保存的是登录时的认证快照。因此以下变化不会主动重写已经签发的 Token：

- 用户被停用；
- 用户角色发生变化；
- 角色 Permission 发生变化；
- Role/Permission 被停用或删除。

当前 Token 会持续到 Logout 或 TTL 到期。若未来业务要求“用户停用/权限修改立即影响全部已签发 Token”，需要增加按用户撤销 Token 的能力或重新设计授权快照策略；V1 不提前建设 Session/Token Index。

## 12. V1 明确排除

Spring Authorization Server、JWT/JWK/Issuer/Audience、Refresh Token、Session 管理、OAuth Client CRUD、Authorization Code/PKCE、OIDC/SSO、SYSTEM/SERVICE 机器身份、Factory/Party Scope 通用框架和安全审计平台。
