## 1. 当前目标

```text
User → Role → Permission → Login → Opaque Token → Gateway → Resource Server → @PreAuthorize
```

当前状态：

- `mom-security`：Redis Opaque Token、TokenStore、Introspector、Servlet Resource Server 已收敛；
- `mom-gateway`：旧 JWT/JWK/Audience/revoked-sid 链已移除，改为 Bearer 边缘检查；
- `mom-auth-platform`：模块、`mom_auth` Schema、5 张核心表和管理员初始化脚本已建立；
- Auth 业务代码下一步按 `controller → service → infrastructure` 实现。

## 2. 模块边界

| 能力 | 权威模块 |
|---|---|
| User / Role / Permission、密码认证、Login、Token、Logout | `mom-auth-platform/mom-auth-server` |
| TokenStore、Opaque introspection、Resource Server | `mom-security` |
| CurrentActor | `mom-core` |
| MyBatis-Plus 审计 | `mom-data` |
| Bearer 边缘检查、Header 清洗、路由、限流、Correlation ID | `mom-gateway` |
| 最终业务授权 | 各业务服务 |

## 3. RBAC

```text
User → UserRole → Role → RolePermission → Permission
```

Role authority 使用 `ROLE_` 前缀，Permission Code 使用稳定业务编码，例如 `mes:work-order:create`。Token 中只保存运行时需要的扁平 `authorities`。

## 4. 登录与 Token

```text
username + password
        ↓
Auth Service 校验
        ↓
加载 Role / Permission
        ↓
聚合 authorities
        ↓
SecureRandom 32 bytes + Base64URL
        ↓
MomTokenPrincipal
        ↓
MomTokenStore.store
        ↓
返回 raw opaque token
```

客户端：

```http
Authorization: Bearer <opaque-token>
```

## 5. Token Principal / Store

```text
MomTokenPrincipal
├── userId
├── authorities
└── expiresAt
```

稳定契约：

```text
Authentication#getName() == userId
```

Redis：

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

Token Store 是认证权威状态，不是 Cache。

## 6. Gateway 边界

Gateway V1 不做真实 Token 认证，但做第一层 Credential 检查：

```text
/api/**
→ 删除外部 X-MOM-*
→ 检查 Authorization 是否存在
→ 必须且只能有一个 Bearer Header
→ token 非空且不含空白
→ 原样转发 Authorization
```

直接拒绝：缺失、非 Bearer、空 Bearer、畸形 Bearer、重复 Authorization，均返回 401。

Gateway 不查询 Redis、不判断 Token 是否存在/过期、不查询 Role/Permission、不使用 JWT/JWK/Issuer/Audience/Session/revoked sid。

登录入口与 CORS `OPTIONS` 放行。

## 7. Resource Server

真正认证发生在业务服务：

```text
BearerTokenAuthenticationFilter
→ OpaqueTokenAuthenticationProvider
→ MomOpaqueTokenIntrospector
→ MomTokenStore.find(token)
→ MomTokenPrincipal
→ GrantedAuthority
→ SecurityContext
→ @PreAuthorize
```

## 8. 服务间 Token 传播

V1 服务间同步调用继续传播**原始 Bearer Credential**，不传播已经计算好的 `userId/roles/permissions` Header。

```text
Gateway
  ↓ bearer
MES Resource Server
  ↓ bearer propagation
WMS Resource Server
  ↓ bearer propagation
QMS Resource Server
```

因此每个 Resource Server 都会独立访问 TokenStore。V1 接受这部分 Redis GET 成本，以保持服务自身安全闭环、Logout 下一跳立即生效，并避免信任可伪造身份 Header。

当前 `mom-openfeign` 尚未实现 Bearer 传播，只已有 Correlation ID 和 CircuitBreaker 命名；该模块暂时冻结，后续单独评估 OpenFeign 与 Spring HTTP Service Clients 后再实现。

传播原则：原样 Bearer、不解析、不查 Redis、不复制 `X-MOM-USER/ROLE/PERMISSION`、无用户请求上下文时不伪造 Token、外部系统不得无差别获得内部 Bearer。

## 9. Logout / Fail Closed

```text
POST /auth/logout
→ MomTokenStore.remove(rawToken)
→ Redis Key 删除
→ 后续任意 Resource Server 立即无效
```

Token 不存在/过期 → 401；Redis/JSON/存储故障 → 基础设施异常，绝不能伪装成 Token 不存在或认证成功。

## 12. V1 明确排除

## 13. 验收基线

```text
Gateway 无/畸形 Bearer       → 401
Gateway 合法 Bearer           → 原样转发
Gateway 外部 X-MOM-*          → 清理
Resource Server 有效 Token    → 200
不存在/过期 Token             → 401
有效 Token + 无权限           → 403
Authentication#getName()      → userId
logout 后同一 Token            → 401
```
