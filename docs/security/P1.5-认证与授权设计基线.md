## 1. 当前目标

```text
User → Role → Permission → Login → Opaque Token → Gateway → Resource Server → @PreAuthorize
```

当前状态：

- `mom-security`：Redis Opaque Token、TokenStore、Introspector、Servlet Resource Server 已收敛；
- `mom-gateway`：旧 JWT/JWK/Audience/revoked-sid 链已移除，当前负责 Bearer 边缘检查、Header 清洗、Gateway 本地限流和统一异常出口；
- `mom-openfeign`：已完成 MOM 内部同步调用的 Correlation ID 与原始 Bearer 传播；
- `mom-auth-platform`：模块、`mom_auth` Schema、5 张核心表和管理员初始化脚本已建立；
- Auth 业务代码下一步按 `controller → service → infrastructure` 实现。

## 2. 模块边界

| 能力 | 权威模块 |
|---|---|
| User / Role / Permission、密码认证、Login、Token、Logout | `mom-auth-platform/mom-auth-server` |
| TokenStore、Opaque introspection、Resource Server | `mom-security` |
| CurrentActor、ErrorCode 纯 Java 契约 | `mom-core` |
| MyBatis-Plus 审计 | `mom-data` |
| Bearer 边缘检查、Header 清洗、路由、限流、Gateway 错误响应 | `mom-gateway` |
| MOM 内部同步 RPC、Correlation ID / Bearer 传播 | `mom-openfeign` |
| 最终业务授权 | 各业务服务 |

`mom-rate-limit` 不再作为独立 Framework Module；Redis 限流实现属于 Gateway 本地基础设施。

## 3. RBAC

```text
User → UserRole → Role → RolePermission → Permission
```

Role authority 使用 `ROLE_` 前缀，Permission Code 使用稳定业务编码，例如 `mes:work-order:create`。Token 中只保存运行时需要的扁平 `authorities`。

## 4. 登录与 Token

```text
username + password
        ↓
Auth Service 校验
        ↓
加载 Role / Permission
        ↓
聚合 authorities
        ↓
SecureRandom 32 bytes + Base64URL
        ↓
MomTokenPrincipal
        ↓
MomTokenStore.store
        ↓
返回 raw opaque token
```

客户端：

```http
Authorization: Bearer <opaque-token>
```

## 5. Token Principal / Store

```text
MomTokenPrincipal
├── userId
├── authorities
└── expiresAt
```

稳定契约：

```text
Authentication#getName() == userId
```

Redis：

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

Token Store 是认证权威状态，不是 Cache。

## 6. Gateway 边界

Gateway V1 不做真实 Token 认证，但做第一层 Credential 检查：

```text
受保护路由
→ 删除外部 X-MOM-*
→ 检查 Authorization 是否存在
→ 必须且只能有一个 Bearer Header
→ token 非空且不含空白
→ 原样转发 Authorization
```

直接拒绝：缺失、非 Bearer、空 Bearer、畸形 Bearer、重复 Authorization，均返回 401。

Gateway 不查询 Redis、不判断 Token 是否存在/过期、不查询 Role/Permission、不使用 JWT/JWK/Issuer/Audience/Session/revoked sid。

登录入口与 CORS `OPTIONS` 放行。

限流使用 Spring Cloud Gateway Redis Token Bucket 机制，但 Fail-Closed 包装、KeyResolver 和异常处理均归 `mom-gateway` 本地所有。Filter/RateLimiter 不手写 JSON；错误通过统一 Gateway 异常处理器输出稳定 `code + message`。

## 7. Resource Server

真正认证发生在业务服务：

```text
BearerTokenAuthenticationFilter
→ OpaqueTokenAuthenticationProvider
→ MomOpaqueTokenIntrospector
→ MomTokenStore.find(token)
→ MomTokenPrincipal
→ GrantedAuthority
→ SecurityContext
→ @PreAuthorize
```

## 8. 服务间 Token 传播

V1 MOM 内部同步调用通过 `mom-openfeign` 继续传播**原始 Bearer Credential**，不传播已经计算好的 `userId/roles/permissions` Header。

```text
Gateway
  ↓ bearer
MES Resource Server
  ↓ bearer via mom-openfeign
WMS Resource Server
  ↓ bearer via mom-openfeign
QMS Resource Server
```

因此每个 Resource Server 都会独立访问 TokenStore。V1 接受这部分 Redis GET 成本，以保持服务自身安全闭环、Logout 下一跳立即生效，并避免信任可伪造身份 Header。

`mom-openfeign` 当前全局传播：

- `X-Correlation-Id`；
- 当前 Servlet 请求中的原始 Bearer Authorization。

传播规则：原样 Bearer、不解析、不查 Redis、不复制 `X-MOM-USER/ROLE/PERMISSION`；Feign 请求已经显式设置 Authorization 时不覆盖；无当前 Servlet 请求、无 Authorization 或非 Bearer 时不传播。

`mom-openfeign` **只允许用于 MOM 内部同步 HTTP RPC**。SAP、LIMS、PCS、AGV 等第三方/外部系统调用不得使用该模块，应使用独立 Integration Adapter、RestClient/WebClient 或厂商 SDK，避免用户 Credential 泄漏到外部边界。

后台任务、Scheduler、MQ Consumer 等无当前用户 HTTP 请求场景，V1 不自动生成 SYSTEM/SERVICE Token。真实机器到机器认证需求出现后再扩展，不提前实现 client_credentials 或默认系统身份。

`mom-openfeign` V1 不再依赖 `mom-resilience`，不预置 CircuitBreaker 命名、全局 Retry 或 Fallback。Resilience 策略必须由真实故障场景驱动后再引入。

## 9. 错误码与国际化预留

`mom-core.ErrorCode` 只定义：

```text
code
messageKey
defaultMessage
```

当前 V1 使用 `code + defaultMessage`。`messageKey` 仅作为未来国际化扩展点，不启用 `MessageSource`、Locale Resolver 或语言资源包。

HTTP 状态、WebFlux/MVC 异常处理和 JSON 序列化不进入 `mom-core`，由各 Web 边界模块自行负责。

## 10. Logout / Fail Closed

```text
POST /auth/logout
→ MomTokenStore.remove(rawToken)
→ Redis Key 删除
→ 后续任意 Resource Server 立即无效
```

Token 不存在/过期 → 401；Redis/JSON/存储故障 → 基础设施异常，绝不能伪装成 Token 不存在或认证成功。

## 14. 验收基线

```text
Gateway 无/畸形 Bearer       → 401
Gateway 合法 Bearer           → 原样转发
Gateway 外部 X-MOM-*          → 清理
Gateway 限流 Redis 不可用      → Fail Closed
Resource Server 有效 Token    → 200
不存在/过期 Token             → 401
有效 Token + 无权限           → 403
Authentication#getName()      → userId
内部 Feign 当前 Bearer         → 原样传播
内部 Feign 无请求上下文        → 不生成 Authorization
logout 后同一 Token            → 401
```
