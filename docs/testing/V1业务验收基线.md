# V1 业务验收基线

> 状态：M00 文档已审核，GitHub 项目管理对象已建立，待 M00 最终签收；以下场景及质量门均为**计划验收条件，尚未执行**。版本范围见[项目基线](../plans/MOM项目基线.md)，需求契约见[需求索引](../requirements/MOM需求索引.md)。本文件不复制[当前实现地图](../当前实现地图.md)或把 CI 通过写成业务通过。

## 1. 样例与证据分层

V1 完整运行一个批次流程制造样例：同厂两款配液产品、真实原料批次、已发布 Formula/路线/质量标准、受控期初、工单、预占领用、实际投料、待检产出、放行、可用库存与正反向追溯。`SC-CFG-01` 用两产品差异，`SC-CFG-02` 用同产品旧/新修订并存检验制造定义配置；二者只证明 B 类制造定义配置，不证明 C 类业务策略或 D 类行业扩展。

第二工厂只在隔离环境发布与读取制造定义，验证不同工厂的定义/配置作用域；不得当作多工厂安全独立运营证据。另维护两个可复核反证样例：`SC-DIS-01` 电子装配（BOM、工序、组件批次/SN、整机 SN、返修）和 `SC-MIX-01` 配液—灌装—包装（液体批次、多个容器、包装单元及损耗）；V1 只要求数据样例、模型差异、契约评审和无法被当前模型表达的证据，完整运行交付属 V3。连续制造单列研究，不借批次通过宣称支持。

证据等级沿用[测试策略](../engineering/standards/testing-strategy-standard.md)：L0 静态/编译，L1 单元，L2 组件，L3 模块集成，L4 打包 Smoke，L5 真实基础设施，L6 跨仓库前后端 E2E。Mock、模拟器、Test Binder、CI、真实环境与人工业务签收各证明不同范围。每份执行记录须注明代码 SHA、环境和数据集、操作人、起止时间、实际结果、关联请求/业务 ID、脱敏日志/截图/数据库核对以及未执行项；不得预填 PASS。

| 场景 | 起点、操作、预期终点 | 需求；首次里程碑；证据门 |
|---|---|---|
| SC-BAT-01 批次闭环 | 已核验原料库存 → 工单下达 → 物料需求/预占/领用 → 实际投料与产出 → 待检不可用 → 授权放行成为可用 → 正反向追到源事实 | `MOM-R-002～009`；分段 `V1-01～06`，全链 `V1-07`；L3/L5/L6 加仓库、生产、质量人员业务签收 |

| SC-CFG-02 跨修订历史 | 旧工单运行时发布新修订；旧单及检验保持旧依据，新单使用新依据，均可追溯 | `MOM-R-001/003/007/009`；`V1-02/05/07`；不可变引用、历史单据与质量结果核对 |
| SC-SEC-01 工厂与权限 | 本厂授权可用；无权、跨厂引用、跨厂操作与查询由目标服务拒绝；第二工厂定义验证使用隔离环境 | `MOM-R-003/004/009`；各入口首次引入时及 `V1-07`；服务端负例、L5 核对 |
| SC-DIS-01 离散反证 | 电子装配最小物料、BOM、组件批次/SN、工序与返修资料，列出 Formula/批次工单无法表达的语义 | `MOM-R-009` 的模型验证；`M00` 基线、`V1-07` 复核；案例数据与契约评审，不宣称运行通过 |
| SC-MIX-01 混合反证 | 配液批次→灌装容器→包装单元，列出段间数量守恒、身份转换与错标异常 | `MOM-R-009` 的模型验证；`M00` 基线、`V1-07` 复核；案例数据与契约评审，不宣称运行通过 |

## 3. 异常矩阵

| 场景 | 注入或拒绝条件；预期业务事实 | 需求；首次里程碑；主要证据 |
|---|---|---|
| SC-E-01 | 定义引用不一致或期初缺可信质量依据/授权：发布或可用库存入账被拒；不伪造历史检验 | `MOM-R-001/002`；`V1-01`；L3＋期初来源人工核对 |
| SC-E-02 | 库存不足、并发预占：无超占、无负库存、重复请求不重复占用 | `MOM-R-004`；`V1-03`；PostgreSQL 并发集成＋余额核对 |
| SC-E-03 | 待检、冻结、过期或跨厂批次：不可预占；批次有效期判定依据在 V1-03 开发前确定 | `MOM-R-004`；`V1-03`；资格规则测试＋L5 拒绝记录 |
| SC-E-04 | 领用或投料重复请求：各 Owner 内只保留一次有效事实，数量不重复变化 | `MOM-R-005`；`V1-03` 验领用部分，`V1-04` 验投料和跨域核对并主验收需求；请求键、库存与投料核对 |
| SC-E-05 | 已领用但未投料、操作暂停或明确失败：不能推断已消耗，保留可恢复差异 | `MOM-R-005`；`V1-04`；跨域事实及操作员可见状态 |
| SC-E-06 | 产出提交后响应丢失、重复回执或服务重启：以原关联核对，既不多产也不丢输入→输出关联 | `MOM-R-005/006`；`V1-04`；L3/L5 故障注入和源事实核对 |
| SC-E-07 | 成品待检或放行被拒：实物库存存在但不可用、不可预占 | `MOM-R-007`；`V1-05`；检验单、库存维度与 API 拒绝 |
| SC-E-08 | 无权或重复放行：只有授权有效判定使可用状态变化，实物总量不重复增加 | `MOM-R-007`；`V1-05`；L3/L5、质量人员签收 |
| SC-E-09 | 谱系源事实缺失、冲突或更正：查询报告不完整及来源，不通过猜测补边或覆盖旧事实 | `MOM-R-006`、`MOM-R-008`；`V1-04` 验源事实，`V1-06` 验查询；关联 ID、源事实与查询结果对照 |

## 4. V1 非功能质量门

**状态说明**：下表只定义首次验证、回归及发布阻断，当前均未执行。`V1-07` 必须逐项汇总结果；若场景未使用 MQ、设备命令或某部署形态，应注明“不适用的具体原因”，不能伪写 PASS。旧 NFR 的逐项适用性见[需求索引](../requirements/MOM需求索引.md#4-旧非功能需求逐项适用性)。

| 门禁与验证归属 | 首次验证里程碑 | 后续回归要求 | V1 发布阻断条件 | 证据形式 |
|---|---|---|---|---|
| **NFG-01 可观测性**；各业务 Owner、运维 | `V1-02` 建立工单关联；每个后续切片验证自身链路 | 新增跨服务调用、消息或关键业务动作时回归，`V1-07` 全链复核 | 工单到库存/质量/追溯故障不能定位，或日志/Trace/指标泄露 Token、使用高基数敏感标签 | L3/L5 的关联 ID、脱敏日志/Trace、低基数指标截图与审计记录 |
| **NFG-02 一致性**；MES、WMS、QMS、Traceability 各事实 Owner | `V1-01` 期初记账；`V1-03` 首次跨域预占；`V1-04/05` 扩至产出和放行 | 每次改变记账、跨域事实或质量转换都跑数据库及故障回归；`V1-07` 对账 | 负库存、超占、重复实物、无法解释的事实缺口、跨 Schema 写入或缺失制造源关联 | PostgreSQL 集成报告、L5 故障注入、交易/余额/工单/源关联核对表 |
| **NFG-03 幂等**；每个写入 Owner | `V1-01` 期初过账；`V1-02～05` 各新增写入首次验证 | 公开命令、消息消费者或模拟器回执变化时回归；`V1-07` 重放全链 | 同请求/回执产生重复工单、预占、领用、投料、产出、放行或库存事实 | L3 并发与同键重放、L5 受控 HTTP/消息回执重放、事实唯一性核对 |
| **NFG-04 恢复**；业务 Owner 与运维 | `V1-01` 期初未知结果；`V1-03/04` 跨域部分失败 | 网络、服务发现、Redis、消息及启动拓扑变化时回归；`V1-07` 注入响应丢失/重启 | 结果未知后自动换键产生新事实，或不能根据原业务标识核对、继续、人工处理 | L5 故障时间线、原请求键/关联 ID、恢复前后数据库核对与操作者可见状态 |
| **NFG-05 权限和工厂边界**；Auth 与各业务 Owner | `V1-01` MDM/WMS 新入口；各后续入口首次开放时 | 新增读写、批量、导出或跨域入口时回归；`V1-07` 全入口核查 | Resource Server 不验 Token/权限，当前业务入口可跨厂引用、操作或查询，或密钥进入仓库 | L2/L3 权限负例、L5 跨厂请求与拒绝记录、密钥检查 |
| **NFG-06 配置历史与审计**；MDM、MES、QMS、WMS | `V1-01` 定义发布；`V1-02` 工单快照；`V1-05` 质量依据 | 定义字段、发布规则或历史事实引用变动时回归；`V1-07` 跑 `SC-CFG-02` | 新修订改写旧单/旧检验依据，缺操作者/来源/时间，或技术时间非 UTC | 新旧修订与工单对照、质量判定、审计记录、时区/日期测试 |
| **NFG-07 迁移与工程基线**；各数据 Owner、发布负责人 | `V1-01` 首次数据库变更；其后每次 Flyway 变更 | 每次迁移和受影响 PR 在 CI 检查；`V1-07` 从批准基线执行升级 | 已发布 Migration 被改写、Schema 漂移、跨 Schema 业务依赖、迁移失败或无法说明应用兼容范围 | CI 工程门禁、Flyway 历史、隔离 PostgreSQL 升级记录和应用版本对应表 |
| **NFG-08 应用回退与发布恢复**；发布负责人、各 Owner | `V1-01` 首次迁移的兼容评审；`V1-07` 完整演练 | 每次影响兼容性、部署入口或关键配置发布时回归 | 不能恢复上一个可用应用版本，数据库与应用不兼容且无前进修复方案，或回退后业务事实丢失 | 隔离环境部署/回退步骤、前后版本读写和事实核对、故障演练报告 |

V1 质量门不自动继承旧 V1 的固定三节点 k3s、10 万谱系边或 100 TPS 数值。`V1-07` 应基于真实部署形态和样例数据批准性能预算并记录测量结果；安全、UTC、Flyway、可靠性及可观测性原则仍须按上述门禁验证。CI 失败阻断 PR，L5/L6 或人工业务证据不足阻断里程碑/版本签收，二者不可替代。

## 5. 执行与签收记录模板

每次场景执行记录：场景 ID、需求 ID、里程碑、`NFG`、代码 SHA、环境与数据集、操作者/业务签收人、步骤和时间、预期/实际事实、异常路径、脱敏证据、未执行项、风险与结论。状态仅用“未执行、通过、失败、阻塞、不适用（附依据）”。失败不得通过删除测试、放宽断言或绕过质量规则改写为通过。

`V1-07` 必须单独形成业务验收记录：生产、仓库、质量人员分别确认其权威事实；项目负责人核查所有发布阻断 `NFG`。GitHub CI 绿色、Issue 关闭或本 M00 文档获批均不构成业务验收通过。
