# 文档维护约定

## 目标

文档必须与同一 Slice 的代码同步交付，并让普通任务以最少上下文找到权威规则。禁止把阶段日志、聊天结论或代码清单长期维护为第二事实源。

## 分层

1. `AGENTS.md`：全局不变量和任务路由。
2. `docs/当前实现地图.md`：稳定实现状态的唯一摘要。
3. `requirements/`、`architecture/`、`engineering/standards/`：需求、当前结构和专题规则。
4. `adr/`：决策历史；被替代 ADR 保留并标记状态。
5. `plans/`：只保留未完成路线与垂直切片，不保存完成流水账。

## 维护规则

- 文档跟随对应代码分支和 PR，不使用固定文档分支。
- 当前事实只写在实现地图；其他文档使用链接，不复制状态表。
- 能从 POM、源码、Migration 或测试直接获得的文件清单、版本数量和测试数量不进入长期文档。
- 完成的实施计划、审计报告和验证快照在约束迁入现行文档后删除。
- 架构决策变化时新增 ADR，并更新旧 ADR 状态；不得改写历史结论伪装成原始决策。
- README 只保留定位、成熟度、技术基线、导航和启动方式。

## Token 约束

- 默认预读链不超过三份文档：`AGENTS.md`、一个主题入口、必要时一个当前 ADR。
- 索引只路由，不复述正文；长文档开头说明适用和无需读取场景。
- 同一规则只有一个权威正文，重复内容改为链接。

## 验证

纯文档变更至少执行：

```bash
git diff --check
bash .github/scripts/validate-engineering-baseline.sh
```

并检查 Markdown 相对链接、已删除文件引用和陈旧实现声明。未执行的运行时验证不得写成通过。
