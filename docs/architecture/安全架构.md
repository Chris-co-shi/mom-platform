# 安全架构

- 状态：Current
- 当前阶段：Mini Auth V1
- 权威设计：[P1.5 认证与授权设计基线](../security/P1.5-认证与授权设计基线.md)
- 决策记录：[ADR-040：Mini Auth 与 Redis Opaque Token 认证基线](../adr/ADR-040-Mini-Auth与Redis-Opaque-Token认证基线.md)
- CurrentActor：[CurrentActor 与数据审计基础](CurrentActor与数据审计.md)

> 当前安全架构以“可控、最小、可运行”为第一目标。旧 JWT、Authorization Server、Refresh Token、OIDC、Session 等方案保留历史记录，但不再是 V1 运行时基线。

## 1. 当前真实状态

`mom-security` 已完成第一版安全基础设施收敛：

- `MomTokenPrincipal`
- `MomTokenStore`
- `MomTokenFingerprint`
- `RedisMomTokenStore`
- `MomOpaqueTokenIntrospector`
- `SecurityCurrentActorProvider`
- Token Store AutoConfiguration
- Servlet Resource Server AutoConfiguration

下一阶段进入 `mom-auth`，完成 User、Role、Permission、Login、Token 签发和 Logout。

## 2. 总体认证链

```text
Client
  │
  │ Authorization: Bearer <opaque-token>
  ↓
Gateway
  │
  │ 原样转发 Bearer Token
  ↓
Business Service
  ↓
BearerTokenAuthenticationFilter
  ↓
OpaqueTokenAuthenticationProvider
  ↓
MomOpaqueTokenIntrospector
  ↓
MomTokenStore
  ↓
Redis
  ↓
OAuth2AuthenticatedPrincipal
  ↓
BearerTokenAuthentication
  ↓
SecurityContextHolder
  ↓
@PreAuthorize
```

Gateway 不是唯一认证点；业务服务仍然独立作为 Resource Server。

## 3. Token 模型

V1 使用高熵随机 Opaque Access Token，不使用 JWT。

推荐生成方式：

```text
SecureRandom
→ 32 random bytes
→ Base64 URL Safe
→ raw opaque token
```

Token 不携带可由客户端解析的业务信息。

认证状态保存在 Redis。

Redis Key：

```text
mom:token:{SHA-256(rawToken)}
```

Redis Value：

```json
{
  "userId": "10001",
  "authorities": [
    "ROLE_ADMIN",
    "mes:work-order:create"
  ],
  "expiresAt": "2026-09-03T10:30:00Z"
}
```

Redis TTL 由 `expiresAt - now` 决定。

## 4. Token Store 边界

`MomTokenStore` 是共享存储契约：

```text
store(token, principal)
find(token)
remove(token)
```

它不暴露：

- Redis Key；
- SHA-256 实现；
- JSON；
- TTL；
- Redis API。

默认实现 `RedisMomTokenStore` 负责这些物理存储细节。

`MomTokenFingerprint` 负责公共规则：

```text
raw token → SHA-256 lowercase hex
```

## 5. Opaque Token Introspection

`MomOpaqueTokenIntrospector` 只负责把原始 Bearer Token 转换成 Spring Security Principal。

职责：

1. `MomTokenStore.find(token)`；
2. Token 不存在时抛出 `BadOpaqueTokenException`；
3. 使用 `Clock` 校验 `expiresAt`；
4. 将字符串 authorities 转换为 `SimpleGrantedAuthority`；
5. 构造 `DefaultOAuth2AuthenticatedPrincipal`。

Principal attributes 第一版只保留：

```text
sub = userId
exp = expiresAt
```

必须保证：

```text
Authentication#getName() == userId
```

## 6. Resource Server 基线

Servlet 业务服务显式开启：

```yaml
mom:
  security:
    resource-server:
      enabled: true
```

默认安全链：

- CSRF disabled；
- `SessionCreationPolicy.STATELESS`；
- `/actuator/health/**`、`/error` 默认公开；
- 其他请求 `authenticated()`；
- Opaque Token Resource Server；
- `@EnableMethodSecurity`；
- 应用自定义 `SecurityFilterChain` 时 framework 退让。

Resource Server 显式开启后，如果依赖的认证 Bean 不完整，应启动失败，不能静默绕过安全。

## 7. 授权模型

第一版只冻结最小 RBAC：

```text
User → Role → Permission
```

Token 运行时统一转换成扁平 authorities：

```text
ROLE_ADMIN
ROLE_OPERATOR
mes:work-order:create
wms:inventory:adjust
```

粗粒度权限可由 Auth 定义；业务服务负责最终业务授权。

例如：

```java
@PreAuthorize("hasAuthority('mes:work-order:create')")
```

但“某用户是否可以启动某张工单”仍可能依赖工单状态、组织归属等领域规则，这部分必须由 MES 自己决定。

## 8. Gateway 边界

Gateway 负责：

- 路由；
- CORS；
- 限流；
- Correlation ID；
- Bearer Token 转发。

Gateway 默认不承担：

- 唯一认证；
- User/Role/Permission 查询；
- 最终 `@PreAuthorize`；
- 业务对象授权。

V1 默认不在 Gateway 和后端 Resource Server 中重复访问 Redis 做两次 Token 认证。

## 9. Logout

Logout 采用 Token Store 删除：

```text
raw bearer token
      ↓
MomTokenStore.remove(token)
      ↓
Redis record deleted
      ↓
立即失效
```

不需要 JWT blacklist、revoked sid、Refresh Session 或 Token Family。

## 10. Fail Closed

Token Store 是认证权威状态，不是普通缓存。

```text
key 不存在
→ invalid token
→ 401
```

```text
Redis 不可用
→ infrastructure failure
→ 不得认证成功
```

Redis、JSON 或其他存储异常不得被转换为 `Optional.empty()`。

## 11. CurrentActor 与审计

认证成功后：

```text
SecurityContextHolder
      ↓
SecurityCurrentActorProvider
      ↓
Authentication#getName()
      ↓
AuditActor(userId, USER)
      ↓
MomMetaObjectHandler
```

因此 `Authentication#getName() == userId` 是安全与数据审计之间的稳定接口契约。

## 12. 自动配置

当前主要安全自动配置：

```text
MomSecurityActorAutoConfiguration
MomSecurityTokenAutoConfiguration
MomServletResourceServerAutoConfiguration
```

`MomSecurityTokenAutoConfiguration`：

- 在 Redis/Jackson 基础设施存在时注册默认 `MomTokenStore`；
- 允许应用覆盖。

`MomServletResourceServerAutoConfiguration`：

- 仅在 Servlet Web Application 且显式 enabled 时生效；
- 默认注册 `MomOpaqueTokenIntrospector`；
- 默认注册 `SecurityFilterChain`；
- 排在 Spring Boot 默认 Servlet Security 自动配置前，避免默认 formLogin/httpBasic 链抢先创建。

## 13. V1 明确排除

当前不建设：

- Spring Authorization Server；
- JWT；
- JWK；
- Issuer / Audience；
- Refresh Token；
- Session；
- Refresh Rotation；
- revoked sid；
- OAuth Client 管理；
- Authorization Code / PKCE；
- OIDC；
- SSO；
- Factory / Party Scope 通用安全框架；
- 安全审计平台。

后续有明确需求时通过新的 ADR 演进，不在当前代码中预埋完整旧体系。
