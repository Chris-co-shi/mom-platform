## 1. 当前真实状态

`mom-security` 已完成 Opaque Token / Redis TokenStore / Resource Server 基础设施。

`mom-gateway` 已移除旧 JWT Decoder、JWK、Issuer、Audience、Session `sid`、revoked-sid Redis 和 Client/UserType 路由授权；当前只保留 Bearer 边缘检查、`X-MOM-*` 清洗、路由、Gateway 本地 Redis 限流和可观测能力。原独立 `mom-rate-limit` Module 已取消，限流实现归属 Gateway。

Gateway 错误统一通过异常处理器序列化为 `code + message`。`mom-core.ErrorCode` 只定义稳定错误契约；`messageKey` 为未来国际化预留，V1 直接使用 `defaultMessage`，不启用 `MessageSource` 或 Locale 解析。

`mom-openfeign` 已收敛为 MOM 内部同步 HTTP RPC 基础设施，全局传播 Correlation ID 和当前 Servlet 请求中的原始 Bearer，不再承载 CircuitBreaker 命名或 `mom-resilience` 依赖。

`mom-auth-platform` 已完成模块、Schema、Flyway 核心表和管理员初始化骨架。

## 2. 总体认证链

```text
Client
  │ Authorization: Bearer <opaque-token>
  ↓
Gateway
  │ Bearer 形态检查
  │ 删除外部 X-MOM-*
  │ 不查 Redis
  ↓
Business Resource Server
  ↓
BearerTokenAuthenticationFilter
  ↓
OpaqueTokenAuthenticationProvider
  ↓
MomOpaqueTokenIntrospector
  ↓
MomTokenStore
  ↓
Redis
  ↓
SecurityContext
  ↓
@PreAuthorize
```

Gateway 是边缘安全和流量入口，不是身份认证权威；业务服务保持独立 Resource Server。

## 3. Gateway 安全边界

负责：

- 受保护路由的 Bearer 第一层检查；
- 删除客户端 `X-MOM-*`；
- 原样转发合法 Authorization；
- 路由、服务发现、负载均衡、CORS、限流、Correlation ID 和可观测性。

第一层拒绝：

```text
Authorization 缺失        → 401
非 Bearer                 → 401
Bearer 为空/畸形           → 401
多个 Authorization         → 401
```

登录入口和 `OPTIONS` 放行。

不负责：TokenStore 查询、Token 存在性/过期、Role/Permission、JWT/JWK、Session/revocation 或最终业务授权。

Gateway Redis 限流异常 Fail Closed，基础设施不可用时由统一 Gateway 异常出口返回稳定错误码；Filter 和 RateLimiter 不手写 JSON 响应。

## 4. Token 模型

```text
SecureRandom
→ 32 random bytes
→ Base64 URL Safe
→ raw opaque token
```

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

`MomTokenPrincipal = userId + authorities + expiresAt`，必须保证 `Authentication#getName() == userId`。

## 5. Resource Server

每个业务服务独立：提取 Bearer → `MomOpaqueTokenIntrospector` → `MomTokenStore.find` → expiresAt → GrantedAuthority → SecurityContext → `@PreAuthorize`。

Token Store 是认证权威状态，不是普通 Cache。

## 6. 服务间身份传播

MOM 内部同步调用通过 `*-client` 与 `mom-openfeign` 完成，例如 MES→WMS、MES→QMS、WMS→MDM。

V1 全局传播当前 Servlet 请求中的原始：

```http
Authorization: Bearer <opaque-token>
```

以及 `X-Correlation-Id`。不传播 `X-MOM-USER/ROLE/PERMISSION` 等认证结果。

```text
MES Resource Server
  ↓ raw bearer via mom-openfeign
WMS Resource Server
  ↓ raw bearer via mom-openfeign
QMS Resource Server
```

每个目标服务再次查询 TokenStore。V1 接受该成本，以换取服务独立认证、Logout 下一跳立即失效和被绕过 Gateway 时仍安全。

传播规则：

1. 当前 Feign 请求已经显式设置 Authorization 时不覆盖；
2. 当前 Servlet 请求存在合法 Bearer 时原样传播；
3. 无当前 Servlet 请求、无 Authorization 或非 Bearer 时不传播；
4. 不解析、不验证、不查 Redis，不在 Feign 层生成 Token；
5. 不传播任何可信身份结果 Header。

`mom-openfeign` 的使用边界是 **MOM 内部同步 RPC**。SAP、LIMS、PCS、AGV 等第三方/外部系统调用不得使用该模块，应通过 Integration Adapter、RestClient/WebClient 或厂商 SDK 建立独立认证策略，避免内部用户 Bearer 泄漏到外部边界。

后台任务、Scheduler、MQ Consumer 等没有当前用户 HTTP 请求的场景，V1 不自动创建 SYSTEM/SERVICE Token。出现真实机器到机器跨服务认证需求后，再单独设计身份与权限模型。

## 7. 授权与 Logout

```text
User → Role → Permission
```

Auth 管理身份和粗粒度权限；业务对象状态、组织归属和流程约束由业务服务决定。

Logout：

```text
MomTokenStore.remove(rawToken)
→ Redis record deleted
→ Token 立即失效
```

Redis/JSON/存储故障必须 Fail Closed。

## 8. CurrentActor 与错误码基础契约

```text
SecurityContextHolder
→ SecurityCurrentActorProvider
→ Authentication#getName()
→ AuditActor(userId, USER)
→ MomMetaObjectHandler
```

`mom-core` 同时提供纯 Java `ErrorCode`：

```text
code           稳定机器码
messageKey     未来国际化预留
defaultMessage V1 默认展示文本
```

`mom-core` 不依赖 HTTP、Spring MVC/WebFlux、`HttpStatus`、`MessageSource` 或 Jackson。具体 HTTP 状态与异常序列化归各 Web 边界模块所有。

## 9. Auth 内部结构

```text
io.github.chrisshi.mom.auth
├── AuthApplication
├── controller
├── service
└── infrastructure
```

```text
controller → service → infrastructure
```

该结构是 Mini Auth V1 的精确简化，不恢复旧 IAM 的 Application/Domain/Repository Port 复杂度。

## 10. V1 明确排除

Spring Authorization Server、JWT/JWK/Issuer/Audience、Refresh Token、Session/revoked sid、OAuth Client 管理、Authorization Code/PKCE、OIDC/SSO、SYSTEM/SERVICE 机器身份、Factory/Party Scope 通用安全框架和安全审计平台。
