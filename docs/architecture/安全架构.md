## 1. 当前真实状态

`mom-security` 已完成 Opaque Token / Redis TokenStore / Resource Server 基础设施。

`mom-gateway` 已移除旧 JWT Decoder、JWK、Issuer、Audience、Session `sid`、revoked-sid Redis 和 Client/UserType 路由授权；当前只保留 Bearer 边缘检查、`X-MOM-*` 清洗、路由、限流和可观测能力。

`mom-auth-platform` 已完成模块、Schema、Flyway 核心表和管理员初始化骨架。

## 2. 总体认证链

```text
Client
  │ Authorization: Bearer <opaque-token>
  ↓
Gateway
  │ Bearer 形态检查
  │ 删除外部 X-MOM-*
  │ 不查 Redis
  ↓
Business Resource Server
  ↓
BearerTokenAuthenticationFilter
  ↓
OpaqueTokenAuthenticationProvider
  ↓
MomOpaqueTokenIntrospector
  ↓
MomTokenStore
  ↓
Redis
  ↓
SecurityContext
  ↓
@PreAuthorize
```

Gateway 是边缘安全和流量入口，不是身份认证权威；业务服务保持独立 Resource Server。

## 3. Gateway 安全边界

负责：

- `/api/**` Bearer 第一层检查；
- 删除客户端 `X-MOM-*`；
- 原样转发合法 Authorization；
- 路由、服务发现、负载均衡、CORS、限流、Correlation ID 和可观测性。

第一层拒绝：

```text
Authorization 缺失        → 401
非 Bearer                 → 401
Bearer 为空/畸形           → 401
多个 Authorization         → 401
```

登录入口和 `OPTIONS` 放行。

不负责：TokenStore 查询、Token 存在性/过期、Role/Permission、JWT/JWK、Session/revocation 或最终业务授权。

## 4. Token 模型

```text
SecureRandom
→ 32 random bytes
→ Base64 URL Safe
→ raw opaque token
```

```text
mom:token:{SHA-256(rawToken)}
→ MomTokenPrincipal JSON + TTL
```

`MomTokenPrincipal = userId + authorities + expiresAt`，必须保证 `Authentication#getName() == userId`。

## 5. Resource Server

每个业务服务独立：提取 Bearer → `MomOpaqueTokenIntrospector` → `MomTokenStore.find` → expiresAt → GrantedAuthority → SecurityContext → `@PreAuthorize`。

Token Store 是认证权威状态，不是普通 Cache。

## 6. 服务间身份传播

MOM 后续存在 MES→WMS、MES→QMS、WMS→MDM 等同步调用。

V1 传播原始：

```http
Authorization: Bearer <opaque-token>
```

不传播 `X-MOM-USER/ROLE/PERMISSION` 等认证结果。

```text
MES Resource Server
  ↓ raw bearer
WMS Resource Server
  ↓ raw bearer
QMS Resource Server
```

每个目标服务再次查询 TokenStore。V1 接受该成本，以换取服务独立认证、Logout 下一跳立即失效和被绕过 Gateway 时仍安全。

当前 `mom-openfeign` 尚未实现 Bearer 传播，只已有 Correlation ID 和 CircuitBreaker 命名；后续单独评估 OpenFeign 与 Spring HTTP Service Clients 后再实现。

SAP、PCS、LIMS、AGV 等外部系统不得无差别继承内部用户 Bearer。

## 7. 授权与 Logout

```text
User → Role → Permission
```

Auth 管理身份和粗粒度权限；业务对象状态、组织归属和流程约束由业务服务决定。

Logout：

```text
MomTokenStore.remove(rawToken)
→ Redis record deleted
→ Token 立即失效
```

Redis/JSON/存储故障必须 Fail Closed。

## 9. Auth 内部结构

```text
io.github.chrisshi.mom.auth
├── AuthApplication
├── controller
├── service
└── infrastructure
```

```text
controller → service → infrastructure
```

该结构是 Mini Auth V1 的精确简化，不恢复旧 IAM 的 Application/Domain/Repository Port 复杂度。

## 10. V1 明确排除

Spring Authorization Server、JWT/JWK/Issuer/Audience、Refresh Token、Session/revoked sid、OAuth Client 管理、Authorization Code/PKCE、OIDC/SSO、Factory/Party Scope 通用安全框架和安全审计平台。
