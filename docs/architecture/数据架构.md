# 数据架构

> 适用于数据所有权、Schema、Migration、跨域查询和长期事实设计。普通字段调整直接读取对应 Entity、Migration 与持久化规范。

## 当前原则

- PostgreSQL 是业务权威存储；服务使用独立 `mom_<context>` Schema。
- Auth 使用 `mom_auth`，System 使用 `mom_system`，MDM 使用 `mom_mdm`，QMS 运行时使用 `mom_qms`。
- 禁止跨 Schema 业务 JOIN、外键、级联写入和共享 Mapper。
- Redis 只保存 Token、限流、缓存和幂等等可重建或明确失效的数据。
- 所有结构变更通过新的 Flyway Migration；不得修改已发布 Migration。
- Java 主键使用 `String`，数据库主键使用 `varchar(19)`；技术时间使用 UTC/`timestamptz`。

## 所有权

- MDM 拥有静态主数据、制造定义和质量基础定义。
- MES、WMS、QMS 分别拥有制造、库存和质量运行时事实。
- Integration 拥有外部请求、映射、重试和对账记录，不拥有领域最终状态。
- Traceability 可维护跨域只读投影，不反向修改来源事实。

质量定义的精确边界见 [ADR-045](../adr/ADR-045-MDM质量基础定义与QMS运行时边界.md)，当前落地状态见 [当前实现地图](../当前实现地图.md)。

## 一致性

- 单服务写入优先使用本地事务。
- 可靠事件采用业务写 + Outbox 同事务；消费写 + Inbox 同事务。
- 不可逆外部副作用不纳入 Seata AT。
- 跨域查询使用 API 组合、本地投影或明确查询服务，不绕过服务边界。

详细规则见 [持久化规范](../engineering/standards/persistence-data-modeling-standard.md)、[数据库表设计规范](../engineering/standards/database-schema-design-standard.md)和[事务一致性规范](../engineering/standards/transaction-consistency-standard.md)。
