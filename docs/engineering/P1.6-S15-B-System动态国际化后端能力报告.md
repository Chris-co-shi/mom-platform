## 2. 范围与架构边界

实现位于 `mom-system-platform/mom-system-server`，遵循：

```text
Web → Application → Domain Port
Infrastructure → Domain Port
Application Transaction → single mom_system PostgreSQL DataSource
```

- Domain 负责 Locale、Code、Message Value、Placeholder、fallback、确定性 JSON 和 checksum；
- Application 负责编排 CRUD、乐观锁、发布、回滚、运行时读取和本地事务；
- Infrastructure 使用参数化 JDBC SQL、affected rows CAS 与 PostgreSQL 行锁实现 Port；
- Web 只映射 HTTP、ETag 和 IAM Authority Reference；
- `mom-system-api` 未增加契约，`mom-system-client` 继续为空，因为当前没有 Java 服务调用方。

未引入生产依赖，未依赖 IAM Server/Schema、MDM API、Redis/Caffeine、MQ、Outbox/Inbox、Seata 或 Feign。

## 3. Flyway V3 与数据模型

V3 新增同一 `mom_system` Schema 的三张表：

1. `system_i18n_resource`：稳定 `applicationCode + resourceCode`、默认 Locale、Kill Switch、当前发布指针、乐观版本与审计；
2. `system_i18n_message`：资源内稳定 `messageKey + locale` Draft、普通文本、启停、乐观版本与审计；
3. `system_i18n_release`：`resourceId + releaseVersion + locale` 主键的完整 JSONB Snapshot、计数、checksum、来源版本和发布审计。

Resource 和 Draft 不提供删除 API，FK 使用同 Schema `ON DELETE RESTRICT`。Release 不包含 `version/updatedAt`，生产 Port 只提供 Insert/Read，数据库触发器额外拒绝 UPDATE/DELETE。`messages_json` 通过 Check 保证 Root 为 JSON Object，checksum 固定为 64 位小写 SHA-256。

## 4. Message 与 Placeholder

V1 Locale 严格限制为 `zh-CN`、`en-US`。Message Value 最大 4096 字符，拒绝 NUL、非法控制字符、`${...}`、`#{...}`、ICU plural/select 形式、非法/空/未闭合 Placeholder 以及明显 JavaScript 入口。

Placeholder 名称只允许：

```regex
[a-zA-Z][a-zA-Z0-9_]*
```

发布时同一 Key 的两个 Locale Placeholder Set 必须完全相同。消息按普通文本保存；服务端不执行 HTML、Markdown、Script、SpEL 或其他表达式。

## 5. Publish 与 Immutable Release

Publish 在单 PostgreSQL 本地事务中：

1. `SELECT ... FOR UPDATE` 锁定单 Resource；
2. 校验客户端 Resource Version 与 enabled；
3. 加载全部 enabled Draft，要求至少一个 Key；
4. 要求每个 Key 存在 defaultLocale Message；
5. 校验 Placeholder Set；
6. 默认 Locale 构建原值快照，另一 Locale 缺失时逐 Key fallback；
7. Key 字典序生成确定性 JSON，以 UTF-8 计算 SHA-256；
8. 与当前双 Locale checksum 相同则返回 409 No-op；
9. 在资源行锁保护下分配 `max(releaseVersion)+1`；
10. 原子插入 `zh-CN/en-US` 两行并推进 Resource 发布指针和审计。

没有 JVM `synchronized` 或 Redis Lock。任一步失败时两个 Locale 和 Resource 指针一并回滚。

## 6. Rollback

Rollback 必须携带目标历史版本、当前 Resource Version 和 changeNote。目标必须完整存在两个 Locale；当前内容相同返回 409。成功时复制历史内容创建新的单调版本，`sourceReleaseVersion` 指向目标版本，Resource 指针只前进，Draft 完全不改变。

## 7. API 与安全

Runtime API：

```http
GET /api/system/i18n/applications/{applicationCode}/resources/{resourceCode}?locale=zh-CN
```

响应只包含稳定双 Code、requested/default Locale、releaseVersion、checksum、fallbackCount、publishedAt 和 messages。它不返回 Draft、数据库 ID 或管理审计。Resource 不存在、禁用、未发布或当前版本不完整均返回 404；读取只选择同一 releaseVersion 的单 Locale Snapshot。

Runtime 使用 `isAuthenticated()`，V1 不允许匿名；checksum 作为强 ETag，匹配 `If-None-Match` 时返回 304 且无 Body。

管理 API 覆盖 Resource/Draft 的创建、更新、启停、查询、分页，Publish、Rollback 和 Release History。权限仅引用 IAM Code：

```text
system:i18n:read
system:i18n:write
system:i18n:publish
```

System 不保存或分配 Permission/Role，不自行解析 JWT，也未关闭现有 SecurityFilterChain。
