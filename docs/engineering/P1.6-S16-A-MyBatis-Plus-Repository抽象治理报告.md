## 2. 被替换的旧规则

旧规则将下列概念近似等同：

```text
禁止 Domain/Application 使用 IService/ServiceImpl
≈
Infrastructure 也不得复用 MyBatis-Plus Repository 抽象
```

该规则保护了领域边界，却使单表 Adapter 重复封装：

- `selectById`；
- `selectOne`；
- `selectList`；
- `selectCount`；
- `insert`；
- `updateById`。

新规则明确拆分：

```text
Domain Repository Port
    保持框架无关

Infrastructure 单表 Adapter
    extends MyBatis-Plus Spring CrudRepository<Mapper, Entity>
    implements MOM Domain Repository Port

Application / Web
    只依赖 Domain Repository Port
```

`IService/ServiceImpl` 继续禁止，显式把 `IRepository` 暴露为 Domain/Application 契约继续禁止。

## 3. MyBatis-Plus 3.5.17 模块事实

执行中通过真实编译发现，最初按旧资料使用了错误包：

```java
com.baomidou.mybatisplus.extension.repository.CrudRepository
```

MyBatis-Plus 3.5.17 的真实模块位置为：

```text
IRepository
→ com.baomidou.mybatisplus.extension.repository.IRepository

Spring CrudRepository
→ com.baomidou.mybatisplus.spring.repository.CrudRepository

Spring IService / ServiceImpl
→ com.baomidou.mybatisplus.spring.service...
```

因此最终门禁同时覆盖：

- 当前 `spring.repository`；
- 当前 `spring.service`；
- extension `IRepository`；
- 历史 extension service 包。

没有自建同名 Repository 抽象，也没有通过新增项目内包装类掩盖依赖事实。

## 4. 规范与门禁

### 4.1 ADR 与持久化规范

新增：

- `docs/adr/ADR-028-MyBatis-Plus-Repository抽象与领域仓储边界.md`

更新：

- `docs/adr/README.md`
- `docs/engineering/standards/persistence-data-modeling-standard.md`

ADR-028 冻结：

1. Domain Repository Port 不继承 `IRepository`、`IService` 或 ORM 接口；
2. 单 Mapper、单 Entity、普通 CRUD 主路径的 Infrastructure Adapter 优先继承 Spring `CrudRepository`；
3. Adapter 必须继续实现框架无关的 MOM Repository Port；
4. Entity、Mapper、Wrapper、`IPage`、affected rows 和数据库异常不得越层泄漏；
5. 多 Mapper、Query/Projection、协议存储和专用 SQL Adapter 不机械迁移；
6. `IService/ServiceImpl`、Active Record、静态 `Db` Helper 继续禁止。

### 4.2 Python Baseline

更新：

- `.github/scripts/validate_java_persistence_baseline.py`
- `.github/scripts/test_validate_java_persistence_baseline.py`

门禁现在阻断：

- 正式 bounded context 引入当前或历史 `IService/ServiceImpl`；
- Infrastructure Repository 之外依赖 Spring `CrudRepository` 或 extension `IRepository`；
- MOM 接口显式继承/实现 `IRepository`；
- `CrudRepository` Adapter 不实现 MOM `*Repository` Port；
- `CrudRepository` Adapter 不使用 `Mybatis*Repository` 命名；
- Domain/Application/Web 导入具体 `Mybatis*Repository`；
- 当前三个明确单表候选退回直接 Mapper 组合。

正反例覆盖当前 `spring.*` 与历史 `extension.*` 包路径。

### 4.3 ArchUnit

更新 `PersistenceArchitectureTest`，新增或修订：

- 当前/历史 MP Generic Service 禁止规则；
- MP Repository 只允许位于 `infrastructure.persistence.repository`；
- Domain Repository Port 不依赖任何 MyBatis-Plus 类型；
- Domain/Application/Web 不依赖具体 Persistence Repository Adapter；
- 三个已批准单表 Adapter 必须可赋值给 Spring `CrudRepository`；
- 直接 JDBC 例外只保留 SAS 官方 Store 精确类。

## 5. 全仓扫描裁决

### 5.1 迁移项

| Adapter | 分类 | 结果 |
|---|---|---|
| `MybatisSystemParameterRepository` | 单 Mapper + 单 Entity + Domain Port + 普通 CRUD 主路径 | 迁移至 `CrudRepository` |
| `MybatisSystemDictionaryRepository` | 单 Mapper + 单 Entity + Domain Port + 普通 CRUD 主路径 | 迁移至 `CrudRepository` |
| `MybatisSystemDictionaryItemRepository` | 单 Mapper + 单 Entity + Domain Port + 普通 CRUD 主路径 | 迁移至 `CrudRepository` |

迁移后使用继承能力：

- `getById`；
- `getOne`；
- `list`；
- `count`；
- `save`；
- `updateById`；
- `getBaseMapper`，仅用于 Parameter 固定 advisory lock。

保留不变：

- Domain Repository 方法；
- Domain/Entity 转换；
- 唯一冲突映射；
- Version CAS；
- 逻辑删除；
- 固定排序与分页；
- 事务、授权与领域校验边界。

### 5.2 System 精确保留项

| Adapter | 保留理由 |
|---|---|
| `MybatisSystemI18nRepository` | 三个 Mapper、多 Entity、发布快照、版本历史和聚合查询 |
| `MybatisSystemUserPreferenceRepository` | 两个 Mapper、Preference/View Setting 两张生命周期不同的表 |

这些类型继续组合 Mapper，不为形式统一强行继承单一 `CrudRepository`。

### 5.3 IAM 精确保留项

IAM Repository 主要属于以下类型：

- 多 Mapper 的授权关系替换；
- Role/User/Permission 聚合；
- Authorization Context 读取聚合；
- OAuth Client Policy 协议投影与受控状态 SQL；
- Session/Security Audit/Admin Read Model 查询；
- 用户安全状态和 Version 条件更新。

这些实现不是普通单表 Domain Port Adapter，机械迁移会扩大通用 CRUD、破坏协议语义或模糊聚合边界，因此保持直接 Mapper/Query 组合。

### 5.4 MDM 与 Integration

MDM Phase 01 技术探针已在 S15-F 退出，当前没有正式业务 Domain Repository 候选。Integration 当前也没有符合本次单表业务迁移条件的 Domain Repository Adapter。
