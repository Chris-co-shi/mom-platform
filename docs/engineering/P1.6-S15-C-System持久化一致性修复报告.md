# P1.6 S15-C：System 持久化一致性修复与项目级门禁

- 日期：2026-07-30
- Base：`main@5562e5ec1c4340dc2de0c5c80f54135df2ae6454`
- 修复起点：`phase/p1.6-system-platform@8831125a9034f40c8c3846083f147e89e6440a36`
- 触发原因：S15-B Dynamic I18n 在 Infrastructure 内新增完整 Spring JDBC Repository，绕开项目统一的 MyBatis/MyBatis-Plus 主键、审计、乐观锁、Mapper 与 SQL 门禁。

## 1. 审计结论

S15-B 的 HTTP、事务、发布、回滚、行锁、不可变 Release、checksum 和 Runtime Fail Closed 语义继续保留；
问题不是必须放弃参数化 SQL或 PostgreSQL 能力，而是同一 `mom-system-server` 出现两套持久化基础设施：

```text
Parameter / Dictionary → MyBatis-Plus + MomBaseMapper + Entity + Mapper XML
Dynamic I18n            → JdbcTemplate + RowMapper + java.sql + 手工 ID/审计/版本
```

同时确认 Parameter 的 Java 注解 SQL 和 Mapper XML 存在正式 `SELECT *`，而既有持久化门禁只解析 Mapper XML，
ArchUnit 也没有禁止正式 bounded context 直接依赖 Spring JDBC/java.sql。

## 2. 修复范围

### 2.1 Dynamic I18n

- 删除 `JdbcSystemI18nRepository`；
- 新增 Resource、Message、Release 三类 Infrastructure Entity；
- Resource/Message 使用 `BaseAuditEntity`、MyBatis-Plus `ASSIGN_ID`、统一 MetaObjectHandler 和 `@Version`；
- Release 保持复合主键追加型快照，不强制继承单主键/逻辑删除基类；
- 新增 Resource、Message、Release 三个 `MomBaseMapper`；
- 行锁、JSONB CAST、发布版本分配、历史聚合与分页使用参数化 Mapper SQL；
- 新增 `MybatisSystemI18nRepository` 继续实现原 Domain Port，Web/Application/Domain 契约不变；
- V3 Flyway 不修改、不删除，也不新增数据库迁移。

### 2.2 Parameter SQL

`SystemParameterMapper` 的注解查询和分页 XML 全部改为显式列名，不再使用 `SELECT *`。排序、过滤、分页、
advisory lock、审计和乐观锁行为保持不变。

### 2.3 项目级门禁

- ArchUnit 对 IAM、MDM、Integration、System 及后续业务 bounded context 禁止直接依赖
  `org.springframework.jdbc..` 和 `java.sql..`；
- 只保留 SAS 官方 JDBC Store、MDM/Integration Seata 技术探针和消息技术消费者四个精确类名例外；
- 新增 Java 持久化扫描器，检查正式 Server Java 中的直接 JDBC、`SELECT *` 和 `${}` 动态 SQL；
- S02 已登记的两个历史注解 `SELECT *` 只按精确文件名暂时保留，不允许增加新例外；
- Engineering Baseline 同时执行原 Flyway/XML 门禁与新增 Java 门禁及正反例测试。

## 3. 冻结后的技术选择

正式业务表默认且强制使用 MyBatis/MyBatis-Plus。复杂 SQL 并不要求退化为通用 CRUD：`FOR UPDATE`、JSONB、
聚合、批量和性能敏感查询可以继续使用 MyBatis 注解或 XML，但不能自行建立第二套 JdbcTemplate/RowMapper/手工
审计体系。新增直接 JDBC 例外必须先有 Accepted ADR、精确类名、技术必要性、测试证据和退出条件。
