## 1. 问题结论

S15-B 的动态国际化行为设计保持有效，但持久化实现连续暴露了三层规范偏差：

```text
JdbcTemplate/RowMapper
→ 改成 MyBatis + 多份 XML
→ 改成 MyBatis-Plus 为主，但 Entity 未统一 BaseEntity、System 仍保留 XML
```

最终标准不是“能通过 MyBatis 访问数据库”，而是：

```text
System 自有正式业务 Entity 全部继承 BaseEntity
+
System Mapper 只使用 MomBaseMapper/Wrapper
+
mom-system-server Mapper XML 数量为 0
```

## 2. Entity 收口

下列六个 System Entity 全部继承 `BaseEntity`，不再局部声明 `version`：

- `SystemParameterEntity`
- `SystemDictionaryEntity`
- `SystemDictionaryItemEntity`
- `SystemI18nResourceEntity`
- `SystemI18nMessageEntity`
- `SystemI18nReleaseEntity`

统一获得：

- String `ASSIGN_ID`
- 创建审计
- 更新审计
- `@Version`
- `@TableLogic`

Release 保持业务不可变；继承 BaseEntity 只是统一数据库行能力，不意味着开放更新或删除。数据库触发器仍拒绝
Release UPDATE/DELETE。

## 3. V4 Migration

V1～V3 不修改。新增：

```text
V4__align_system_entities_with_base_entity.sql
```

V4：

- 为 Parameter、Dictionary、DictionaryItem、I18n Resource、I18n Message、I18n Release 增加 `deleted`；
- 为 Release 增加 `id/created_by/created_at/updated_by/updated_at/version`；
- 为历史 Release 回填 19 位 String 技术 ID 与审计字段；
- Release 主键调整为 `id`；
- 原 `(resource_id, release_version, locale)` 改为唯一约束；
- 重建 Release 不可变触发器。

## 4. System XML 清零

删除全部 System Mapper XML：

```text
SystemParameterMapper.xml
SystemDictionaryMapper.xml
SystemDictionaryItemMapper.xml
SystemI18nReleaseMapper.xml
```

最终：

```text
mom-system-server/src/main/resources/mapper/** = empty
```

Parameter、Dictionary、DictionaryItem、I18n Resource/Message/Release 的 CRUD、查询、计数、排序与分页统一使用
`MomBaseMapper` 和 Wrapper。

PostgreSQL 特性处理：

- Parameter advisory lock：一条固定参数化 Mapper 注解；
- Release JSONB：`mom-data` 统一 `PostgresqlJsonbStringTypeHandler`；
- 下一版本与 distinct 历史：受控 QueryWrapper select expression；
- 历史聚合：先读取受控版本集合，再由 Java 分组并校验同版本审计一致性；
- Resource 行锁：固定 `FOR UPDATE` Wrapper 尾句。
