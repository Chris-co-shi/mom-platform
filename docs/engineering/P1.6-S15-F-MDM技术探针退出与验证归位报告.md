本 Slice 解决 S15-E 暴露出的职责问题：MDM 的 Entity、Mapper 和 Configuration 虽已进入标准 Package，但其内容仍是 Phase 01 PostgreSQL、Outbox、RocketMQ、Seata、OpenFeign 和跨服务 Trace 技术探针。目录合规不代表这些类型应继续存在于正式 bounded context。

## 2. 决策

正式 MDM Server 只承载真实主数据业务能力，不再充当基础设施 PoC 或 Smoke Fixture 宿主。

因此执行以下决策：

1. 删除 MDM 正式生产源码中的 Data、Outbox、Seata 和 Service Discovery 技术探针；
2. 删除仅为这些探针存在的 API、Client、Controller、配置和依赖；
3. 删除与 MDM 探针耦合的 Integration 对端技术契约和运行时实现；
4. 历史 Flyway Migration 保持不可变，通过 `V101` fail-closed 退出剩余技术表；
5. MDM PostgreSQL 和 Nacos 继续进行真实打包应用 Smoke，但不再通过伪业务 CRUD 接口验收；
6. Messaging、Seata 和 Observability 删除无真实调用方的历史端到端 PoC，保留 Framework、配置和打包兼容性验证；
7. 首个真实业务事件、短全局事务或跨服务调用 Slice 必须重新建立对应真实运行时验收，当前 Framework 验证不得被描述为等价的 Broker、TC 或端到端 Trace 验收。

## 3. 删除的 MDM 正式生产代码

### 3.1 Data Probe

删除：

- `MdmDataProbeService`
- `MdmDataProbeEntity`
- `MdmDataProbeMapper`
- `MdmDataProbeAutoConfiguration`
- `MdmDataProbeController`
- `MdmDataProbeRequest`
- `MdmDataProbeResponse`

原调用链为 `Controller → Application Service → Mapper → technical_data_probe`，Application 直接依赖 MyBatis Mapper，不符合 `Web → Application → Domain Port ← Infrastructure Adapter`。

### 3.2 Outbox Probe

删除：

- `MdmOutboxProbeService`
- `MdmOutboxProbeController`
- `MdmOutboxProbeRequest`
- `MdmOutboxProbeResponse`

这些类型只验证技术表写入与 Outbox 追加的本地事务，不是正式 MDM 领域事件用例。

### 3.3 Seata AT Probe

删除：

- `MdmSeataAtLocalParticipantService`
- `MdmSeataAtProbeService`
- `MdmSeataAtProbeController`
- `MdmSeataAtProbeRequest`
- `MdmSeataAtProbeResponse`

其中本地参与者直接使用 `JdbcTemplate` 和 `java.sql.Timestamp`，只服务于双 PostgreSQL 技术 PoC，不得作为正式 Application 实现保留。

### 3.4 Service Probe

删除：

- `MdmServiceProbeController`
- `MdmServiceProbeResponse`
- `MdmServiceProbeClient`

`MomMdmApplication` 同步移除为 Seata PoC 注册的 `@EnableFeignClients`，恢复为最小 bounded context 启动入口。

MDM 正式生产源码共删除 17 个 Probe 类型，另删除 MDM API/Client 中 2 个 Probe 契约类型。

## 6. 数据库退出策略

历史 Versioned Migration 未修改、未删除、未重命名。

新增：

- `mom_mdm/V101__retire_remaining_phase01_technical_tables.sql`
- `mom_integration/V101__retire_remaining_phase01_infrastructure_tables.sql`

选择 `V101` 的原因：测试资源已有 `V100__create_test_technical_tables.sql`，并且既有环境可能已经执行到 V100。低版本补丁会被已有环境跳过，也无法在测试环境中清理 V100 重建的技术表。

MDM V101 退出：

- `technical_data_probe`
- `mom_outbox_event`
- `technical_seata_at_coordinator`
- `undo_log`

Integration V101 退出：

- `technical_message_receipt`
- `mom_inbox_event`
- `technical_seata_at_participant`
- `undo_log`

两个 Migration 均先逐表检查行数。任一表非空则 `RAISE EXCEPTION` 并阻止升级，不静默删除潜在环境数据；空表或不存在时才执行 `DROP TABLE IF EXISTS`。

测试资源 V100 仅用于证明 V101 能从历史技术结构安全升级，不进入正式打包产物，也不再承载技术能力验收。
