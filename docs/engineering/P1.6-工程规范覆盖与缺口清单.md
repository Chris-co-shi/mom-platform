## S06 新增结论

1. `docs/engineering/P1.6-S06-IAM端点调用方与职责审计.md` 是 S06 的权威证据矩阵。
2. 三个 PC Web 当前实际使用第一方 JSON；Mobile 当前实际使用系统浏览器 Authorization Code + PKCE S256。
3. 标准 Refresh Grant 与 JSON Refresh 共享同一 Session/Refresh 权威核心，不能按“重复实现”直接删除。
4. Mobile 服务端 Logout、业务 Resource Server revoked sid 等价能力、Mobile Redirect URI 分环境矩阵和 Web 标准 PKCE 包长期产品状态进入 S07、S08、S10。
5. `IamAuthorizationServerConfiguration`、`IamDirectAuthenticationController`、`IamAdminService` 只登记为后续行为保持 Refactor Candidate。
6. Chris 接受固定远程 Ref、GitHub 可复核增量、最终 Head Engineering Baseline、JDK 25 全 Reactor `clean verify` 和必需 Actions 作为本次纯 Markdown审计证据；该裁决不扩展到后续 Slice。
7. S06 未修改认证协议、公开 API、Token、Session、Refresh、Permission、Schema 或 Flyway。

## S07-A Proposed 结论

1. 新增 `ADR-024-PC-JSON与Mobile-PKCE-OIDC双通道.md`，状态为 Proposed。
2. 推荐 PC 第一方 JSON 与 Mobile Authorization Code/PKCE/OIDC 双通道长期并存，共享单一 Session、Refresh、JWT 和撤销权威核心。
3. 方案 B 仅作为未来可评估方向；方案 C Rejected；方案 D Deferred。
4. EG-01 已形成 Mobile Logout 目标安全语义，但未创建 API、未实施运行时。
5. EG-02 保留至 S08/S10；S07 不实现 Filter、Redis 查询或网络调用。
6. EG-03 已形成 Redirect URI 精确登记、禁止通配、分环境原则和占位矩阵；正式值待确认。
7. EG-04 的 Proposed 产品状态为 `Compatibility / Future Migration Capability`；当前不删除、不接线、不描述为生产 Runtime。
8. 双通道一致性矩阵明确区分完全一致的安全语义、协议差异、PC 专属和 Mobile/OIDC 专属行为。
9. S08/S09 重构不得改变外部协议与安全语义；任何迁移、删除、BFF、公开 API 或正式 Client/Redirect 变更仍需 Chris 单独批准。
