## S06 新增结论

1. `docs/engineering/P1.6-S06-IAM端点调用方与职责审计.md` 是 S06 的权威证据矩阵。
2. 三个 PC Web 当前实际使用第一方 JSON；Mobile 当前实际使用系统浏览器 Authorization Code + PKCE S256。
3. 标准 Refresh Grant 与 JSON Refresh 共享同一 Session/Refresh 权威核心，不能按“重复实现”直接删除。
4. Mobile 服务端 Logout、业务 Resource Server revoked sid 等价能力和 Mobile Redirect URI 分环境矩阵仍是 Evidence Gap。
5. `IamAuthorizationServerConfiguration`、`IamDirectAuthenticationController`、`IamAdminService` 只登记为后续行为保持 Refactor Candidate。
6. S06 不创建 S07 ADR，不修改认证协议、公开 API、Token、Session、Refresh、Permission、Schema 或 Flyway。

## 优先级结论

1. S01～S05 均为规范与门禁 Slice，没有提前建设 System 业务。
2. S06 只审计真实调用方和职责，不删除、合并或重写既有认证入口。
3. 现有 Spring Authorization Server JDBC Store、Refresh Rotation、Reuse Detection、Session 撤销与 JWT 校验均保持。
4. S07 未经 Chris 批准不得形成 Accepted 双通道 ADR或实施迁移。
5. 国际化动态资源、复杂弃用平台和跨仓库契约生成若无真实调用方，分别推迟到 S15 或 P1.7。
