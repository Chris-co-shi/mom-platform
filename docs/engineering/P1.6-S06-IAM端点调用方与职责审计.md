## 1. 审计目标与分类口径

S06 回答以下问题：

1. 当前 IAM 暴露哪些协议端点、第一方端点和管理端点；
2. mom-web、mom-mobile、Gateway 与业务 Resource Server 实际调用或依赖哪些能力；
3. 同名或相似流程是重复实现，还是不同外部协议对同一权威核心的 Adapter；
4. 哪些类承担过多职责，后续可在行为保持前提下拆分；
5. S07 必须裁决哪些长期协议边界，哪些结论尚不能在 S06 提前接受。

| 分类 | 含义 |
|---|---|
| Current Required | 已存在真实调用方或当前安全闭环依赖，不能删除 |
| Compatibility Boundary | 当前调用较少或未接入主流程，但属于稳定兼容面，删除前需要独立证据和批准 |
| Protocol Adapter | 面向不同协议的适配层；只要共享同一权威核心，就不因入口不同自动判定为重复模型 |
| Refactor Candidate | 职责过宽或组装过密，可在后续 Slice 做无行为拆分 |
| Evidence Gap | 当前证据不足以支持删除、合并或宣布端到端安全闭环完成 |
| S07 Decision Input | 只向 S07 提供事实、选项和风险，不构成 Accepted ADR |

## 2. 当前认证与授权拓扑

```text
PC Web（Admin / Supplier / Customer）
  → Gateway
  → POST /api/iam/auth/login
  → POST /api/iam/auth/password/change-required
  → POST /api/iam/auth/refresh
  → POST /api/iam/auth/logout
  → GET  /api/iam/me
  → /api/iam/admin/**（仅 Admin）

Mobile PDA
  → 系统浏览器
  → /oauth2/authorize
  → IAM /login + MOM_IAM_SESSION Cookie + CSRF
  → Authorization Code + PKCE S256
  → /oauth2/token
  → ID Token / JWK / Issuer / Audience / Nonce 校验
  → Gateway /api/iam/me
  → Gateway /api/** Bearer API

两条签发入口
  → IamSessionTokenService
  → iam_user_session + iam_refresh_token
  → 单 ACTIVE Refresh、Rotation、Reuse Detection
  → JWT Access Token（sid / client_id / user_type / roles / permissions / scopes）
  → Redis revoked sid
```

核心结论：PC JSON 与标准 OAuth2/OIDC 是两种外部协议 Adapter，但 Session、Opaque Refresh、
Rotation、Reuse Detection、JWT 和 revoked sid 由同一套后端权威服务承担；当前没有第二套
Session/Refresh 权威模型。

### 4.1 PC Web Token 边界

当前三个 PC Web 应用：

- Access Token 与 Refresh Token 仅写 `sessionStorage`；
- 不写 `localStorage`、Cookie、URL 或 Pinia 持久化；
- API 使用 Bearer Token，`credentials: omit`；
- 401 最多触发一次 Single Flight Refresh；
- 403 可刷新授权上下文；只读请求允许一次重试，高风险写命令不静默重放。

这是当前已实现边界，不等于 S07 已经决定永久放弃标准浏览器 PKCE，也不构成 BFF 决策。

### 4.2 Mobile Token 边界

当前 Mobile：

- 系统浏览器打开 Authorization Endpoint；
- 生成 `state`、`nonce`、`code_verifier` 和 S256 `code_challenge`；
- 回调校验 App Link/Redirect、`state`，然后交换 Authorization Code；
- 校验 ID Token 的 Issuer、JWK 签名、Audience 和 Nonce；
- Refresh Token 通过安全存储 Lease/Replacement 语义轮换，结果不确定时 Fail Closed；
- Access Token 只在运行时内存中使用；
- Bearer 业务请求只允许发往配置的 Gateway 同源 `/api/` 路径。

## 5. Session、Refresh 与撤销职责

### 5.1 单一权威核心

`IamSessionTokenService` 是两条外部协议共享的 Session/Refresh 权威服务：

1. `issueInitial` 创建绝对 Session 和 sequence=1 Opaque Refresh；
2. `rotate` 使用数据库行锁消费唯一 ACTIVE Token；
3. 旧 ROTATED Token 再次出现时标记 Session `COMPROMISED`；
4. 每次成功轮换创建唯一后继并推进序号；
5. 过期、撤销和重放均写 revoked sid，TTL 覆盖已签发 Access Token；
6. Refresh Token 只保存摘要，明文只存在于本次响应和客户端安全边界。

因此：

- `IamRefreshGrantAuthenticationProvider` 是标准 OAuth2 Refresh Adapter；
- `IamDirectAuthenticationController.refresh` 是第一方 JSON Refresh Adapter；
- 两者外部响应形态不同，但都调用 `IamSessionTokenService.rotate`；
- 当前应分类为“共享核心的双 Adapter”，不是“可立即删除的一套重复 Refresh 实现”。

### 5.2 Gateway 与业务 Resource Server

Gateway 当前对 `/api/**`：

- 独立验证 JWT Issuer、JWK、Audience；
- 清理客户端伪造的 `X-MOM-*` Header；
- 校验 Client 路由边界；
- 查询 Redis revoked sid；
- Redis 超时或故障返回 503，Fail Closed；
- 保留原始 Bearer Token 转发给下游。

通用 Servlet Resource Server AutoConfiguration 当前独立验证 JWT 和 Audience，并要求业务代码完成最终
Permission、Factory/Party 与对象归属判断；但该通用配置未包含 revoked sid 检查。当前文档不能据此宣称
“所有业务服务在绕过 Gateway 时也具备等价实时撤销”。这属于 S08/S10 前必须保留的 Evidence Gap。

## 7. 重复流程判定

| 候选 | 判定 | 原因 |
|---|---|---|
| JSON Login vs IAM HTML/Form Login | 非重复 | 前者服务 PC 第一方页面；后者服务 Authorization Endpoint 中的用户认证和保存请求续接 |
| JSON Refresh vs OAuth2 Refresh Grant | 非重复外部协议；共享核心 | 两者均调用同一 `IamSessionTokenService.rotate`，协议请求与响应不同 |
| JSON Logout vs OIDC Logout | 非重复 | JSON Logout 由 Bearer `sid` 撤销权威 Session；OIDC Logout 是浏览器协议边界 |
| mom-web `first-party-auth` vs `auth` | 功能重叠候选，但不能删除 | 当前三个应用只接入第一方包；标准包仍是已实现兼容能力，S07 必须裁决长期方向 |
| Gateway JWT vs 业务服务 JWT | 非重复 | Gateway 做入口与粗粒度隔离；业务服务独立验证 Token 并做最终授权 |
| Gateway revoked sid vs 业务服务缺少 revoked sid | Evidence Gap | 不是重复，而是等价安全能力尚未在通用业务 Resource Server 中得到证明 |
| Controller 内 Token JSON 拼装 vs `IamTokenResponseHandler` | Refactor Candidate | 可共享内部响应构造理念，但不能把 OAuth2 响应强制改成第一方 JSON 契约 |

## 8. 已确认的证据缺口与风险

### EG-01：Mobile Logout 未撤销服务端 Session

当前 `MobileAuthRuntime.logout()` 只清理本地授权事务、安全存储、Access Token 和运行时上下文，
未调用 JSON Logout、OIDC End Session 或专用撤销端点。结果是客户端已退出，但权威 Session 可能继续保持
ACTIVE，直到绝对期限、Refresh 失败、管理员撤销或其他安全事件终止。

S06 只记录事实；S07 必须决定 Mobile 的长期 Logout 协议和兼容策略。

### EG-02：业务 Resource Server 的 revoked sid 等价能力未闭环

Gateway 已实现 revoked sid Fail Closed；通用 Servlet Resource Server 只验证 JWT/JWK/Issuer/Audience。
如果业务服务在任何部署场景可被直接访问，则仅靠短期 JWT 到期不能等价于实时 Session 撤销。

S06 不实现过滤器；S08/S10 必须结合部署拓扑、直连边界和测试证据完成裁决与回归。

### EG-03：Mobile 默认开发 Redirect URI 与 IAM 默认注册值不一致

IAM 默认 Mobile Redirect 是 `com.mom.mobile:/oauth2/callback`；mom-mobile Runtime 的默认开发值是
`http://127.0.0.1:5173/oauth2/callback`，正式环境又要求 HTTPS App Link。当前必须通过环境配置覆盖才能匹配
具体运行形态。S10 跨仓库 E2E 前必须锁定 H5、本地 Android 与正式 App Link 的分环境矩阵。

### EG-04：Web 标准 PKCE 包的产品状态未裁决

`packages/auth` 具备完整 PKCE/OIDC/Refresh/Logout 实现和测试，但三个当前 Web 应用均接入
`first-party-auth`。它可以是未来迁移 Adapter，也可能是历史兼容包；S06 没有权限将“未接入当前应用”
等价为“可删除”。

EG-01～EG-04 继续作为 S07、S08 和 S10 的架构与回归输入，但不阻止 S06 文档审计完成。

## 9. S07 决策输入（非 ADR）

### 9.1 已冻结事实

1. Mobile 当前真实依赖标准 Authorization Code + PKCE S256、OIDC ID Token/JWK 和 IAM HTML 登录页；
2. 三个 PC Web 当前真实依赖第一方 JSON 登录、改密、Refresh 和 Logout；
3. 两条入口共享同一 Session/Refresh/JWT/撤销权威核心；
4. Gateway Bearer API 和各业务 Resource Server 的 JWT 独立校验边界不能因前端协议选择而取消；
5. 任何入口删除都需要跨仓库调用方迁移、兼容窗口、回归证据和 Chris 明确批准。

### 9.2 候选方向

| 选项 | 描述 | 主要收益 | 主要风险 |
|---|---|---|---|
| A | 保留 PC JSON + Mobile PKCE/OIDC 双通道，共享权威核心 | 与当前真实调用一致，迁移风险最低 | 需要持续维护两个协议 Adapter 和一致行为测试 |
| B | PC 逐步迁移到标准 PKCE/OIDC，JSON 进入兼容期 | 长期协议统一 | Web Token/UX/跨端回调迁移成本高，必须证明安全与产品收益 |
| C | Mobile 改为第一方 JSON | 表面入口减少 | 弱化系统浏览器、PKCE、OIDC 和 App Link 安全边界，不符合当前 Mobile 实现与既有设计 |
| D | 引入 BFF，由服务端持有 Token | 浏览器凭证边界更强 | 新增 BFF、Cookie Session、CSRF、部署与运维复杂度，超出当前 S06/S07默认范围 |

S06 不选择任何选项。S07 只有在 Chris 明确批准后才能形成 Accepted ADR。

- RFC 6749：OAuth 2.0 Authorization Framework；
- RFC 7636：Authorization Code PKCE；
- RFC 9700：OAuth 2.0 Security Best Current Practice；
- OpenID Connect Core 1.0：ID Token、Issuer、Audience、Nonce；
- RFC 7009：OAuth 2.0 Token Revocation。

官方规范只用于解释协议边界；MOM 当前调用事实以三个仓库固定 Ref 的源码为准。

## 12. S06 结论

1. 当前没有足够证据删除 SAS/OIDC、IAM HTML Login、第一方 JSON 或任一 Refresh Adapter；
2. 两套 Refresh 入口共享同一 Rotation 权威核心，不是两套安全模型；
3. PC Web 与 Mobile 当前采用不同协议，属于 S07 必须明确批准的长期双通道决策；
4. `IamAuthorizationServerConfiguration`、`IamDirectAuthenticationController`、`IamAdminService`
   是后续行为保持重构候选，但 S06 不修改代码；
5. Mobile 服务端 Logout、业务 Resource Server revoked sid 等价能力、Mobile Redirect URI 分环境矩阵、
   Web 标准 PKCE 包长期产品状态继续作为 S07、S08 和 S10 输入，均未解决；
6. `S06: Completed`；`S07: Not Started`。
