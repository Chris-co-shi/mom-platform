## 2. 重构前职责图

```text
IamAdminController
  → IamAdminService
      ├─ 用户查询/创建/更新/状态/解锁/重置/删除
      ├─ 用户 Role/Factory/Mobile/Party
      ├─ Role/Permission
      ├─ Session 查询与撤销
      ├─ Client Policy
      ├─ Security Audit 查询与成功事件构造
      └─ 输入、行锁、Version、最后管理员、Session 撤销协调
```

`IamAdminService` 约 730 行，同时依赖用户、角色、关系、Session、Client、审计和安全基础
设施，共有 16 个本地事务写入口。

## 3. 重构后职责图

```text
IamAdminController
  → IamAdminService (compatibility facade; no transaction/repository)
      ├─ IamUserAdminApplicationService
      ├─ IamUserAuthorizationApplicationService
      ├─ IamRoleAdminApplicationService
      ├─ IamSessionAdminApplicationService
      ├─ IamClientAdminApplicationService
      └─ IamSecurityAuditQueryService

Application Services
  → IamAdminOperationSupport
      ├─ Permission / current actor
      ├─ user lock / last platform-admin guard

      └─ append-only security audit construction

```

### 3.1 Application Service 拆分

| 服务 | 用例所有权 |
|---|---|
| `IamUserAdminApplicationService` | User 查询、创建、更新、状态、解锁、凭证重置、删除 |
| `IamUserAuthorizationApplicationService` | User Authorization Snapshot、Role、Factory Scope、Mobile Access、Party Binding |
| `IamRoleAdminApplicationService` | Role 目录、Role Permission Snapshot 与全量替换 |
| `IamSessionAdminApplicationService` | Session 查询、单 Session 撤销、用户全部 Session 撤销 |
| `IamClientAdminApplicationService` | Client Policy 查询与状态变更 |
| `IamSecurityAuditQueryService` | 安全审计只读查询 |

### 3.2 Facade 保留原因

`IamAdminController` 继续只注入 `IamAdminService`，其 Path、Method、Request Body Java 类型、
序列化字段和条件 Bean 边界均不变。Facade 仅委托，不持有 Repository，不含业务分支，
也不重复开启事务。这比让 Controller 一次注入六个服务的变更面更小。

## 4. 事务、锁、Version 与审计等价

1. 原 16 个 `@Transactional` 写方法各自完整迁入对应 public、非 final Application Service 方法；
2. Facade 不含 `@Transactional`，不形成嵌套或拆分事务；
3. 用户写入仍先锁用户行，角色写入仍先锁角色行；
4. 减少 PLATFORM_ADMIN 前仍先锁唯一内置角色并重新计数；
5. 关系全量替换、父聚合版本推进与成功审计仍位于同一事务；
6. 禁用用户、凭证重置、禁用 Mobile、Party Rebind 和 Client 禁用的 Session 撤销顺序不变；
7. 外部 Factory 校验不可用时仍在任何关系、Version 或成功审计写入前 Fail Closed；
8. 未引入 `REQUIRES_NEW`、异步事件、`@Lazy`、`@Primary` 或 Controller 事务。

`IamAdminTransactionBoundaryTest` 精确锁定事务所有者；`IamAdminServiceCharacterizationTest`
锁定自操作、最后管理员、Factory Fail Closed、Stale Version、内置角色与 Mobile
撤销/版本/审计顺序。

## 5. 安全不变量

- 禁止禁用、删除和管理员重置自己；
- 最后一名有效 PLATFORM_ADMIN 保护与共享行锁不变；
- 内置角色及其 Permission 仍只读/Flyway 管理；
- 外部 Party/Factory 规则仍由 Domain Rule 与权威 Verifier 判定；
- 不保留 Mobile Access 或 Party Binding 时仍撤销 Session；
- 失败不推进父版本，不写成功审计。

## 6. 错误分类与 HTTP 映射

Admin 对外仍严格使用：

```json
{"code":"...","message":"..."}
```

内部用 `IamAdminErrorResponse` record 取代无类型 `Map`，JSON 仍只有两个字段。

| 内部分类 | HTTP | code |
|---|---:|---|
| Not Found | 404 | `not_found` |
| Stale Version | 409 | `stale_version` |
| Conflict / 脱敏 Data Integrity / 已知 State Conflict | 409 | `conflict` |
| Dependency Unavailable | 503 | `dependency_unavailable` |
| Invalid Request | 400 | `invalid_request` |
| Access Denied | 403 | `forbidden` |

`DataIntegrityViolationException` 仍固定映射为“操作违反唯一性、引用或并发约束”，不回显
SQL、约束名、堆栈、Token 或底层端点。Admin、第一方认证、OAuth2/OIDC、Spring Security
和 Gateway 错误模型继续分离。

## 7. Token Adapter 边界

源码审计结论：

1. `IamRefreshGrantAuthenticationProvider` 仍只验证 SAS Client Principal/Refresh Grant，调用唯一
   `IamSessionTokenService.rotate`、唯一 `IamAccessTokenIssuer`，再映射为 SAS Token；
2. `IamDirectAuthenticationController#refresh` 仍使用同一 Rotation 和 Issuer，映射为第一方 JSON；
3. `IamTokenResponseHandler` 仍保留 `access_token`/`token_type`/`expires_in`/`scope`/
   `refresh_token`、UTF-8 JSON、`no-store`/`no-cache` 和附加参数 Fail Closed；
4. `invalid_client`、`unauthorized_client`、Rotation `invalid_grant` 仍使用 OAuth2 标准错误；
5. 标准与第一方响应格式是必要的 Adapter 差异，没有可安全抽取的第三份重复逻辑。

因此 S09 不新建无价值 Token Mapper，不修改 Token 生产代码，不删除任何 Adapter。
`IamRefreshGrantAuthenticationProviderTest` 和扩展后的 `IamOAuth2ProtocolCharacterizationTest`
提供上述证据。

## 8. Admin 契约等价证据

`IamAdminControllerContractTest` 精确锁定全部现有 Admin Path/Method、创建/204 状态、
limit/offset 默认值与 Request record 字段类型。`IamAdminExceptionHandlerTest` 锁定
HTTP 状态、code、message、Content-Type 和两字段 JSON。Controller 文件未修改。

Permission Code 全部从原 Facade 原样迁移；新服务不增加、删除或重命名任何管理权限。

## 9. Session/Refresh 未变

- `IamSessionTokenService`、`IamRefreshGrantAuthenticationToken`、`IamAccessTokenIssuer` 代码未修改；
- Rotation、单 ACTIVE Refresh、Reuse Detection、绝对期限和 revoked sid 路径未修改；
- Admin 撤销仍同步调用唯一 `IamSessionTokenService`；
- 标准 Refresh 与第一方 Refresh 仍是两个协议 Adapter、一个安全核心。
