## 2. 最终技术选择

### 2.1 Resource 与 Draft Message

Resource、Message 使用：

- `BaseAuditEntity`；
- MyBatis-Plus `ASSIGN_ID`；
- 统一 `MetaObjectHandler`；
- `@Version`；
- `MomBaseMapper`；
- Repository 内的 `LambdaQueryWrapper`。

普通 Insert、Update、主键读取、稳定 Code 查询、父资源限定、启用列表、计数、固定排序和分页均由
MyBatis-Plus 表达，不再维护 `SystemI18nResourceMapper.xml` 或 `SystemI18nMessageMapper.xml`。

Resource 的发布/回滚行锁使用服务端固定 `FOR UPDATE` Wrapper 尾句。分页尾句只拼接 Application 已验证的
非负 page/size 结果，不接受客户端 SQL 标识符、表达式或原始文本。

### 2.2 Immutable Release

Release 保持复合主键追加型快照，不强迫继承通用单主键/逻辑删除基类。唯一保留的
`SystemI18nReleaseMapper.xml` 只承担 MyBatis-Plus 普通单表 DSL 不适合表达的数据库能力：

- `messages_json` 的 PostgreSQL `jsonb` CAST 与文本读取；
- 资源行锁保护下的下一发布版本聚合；
- 版本级历史聚合投影；
- `count(DISTINCT release_version)`。

Release 仍只允许 Insert/Read，数据库触发器继续拒绝 Update/Delete。

### 2.3 System XML 收敛

System Mapper XML 从 6 份收敛为 4 份：

```text
SystemParameterMapper.xml
SystemDictionaryMapper.xml
SystemDictionaryItemMapper.xml
SystemI18nReleaseMapper.xml
```

I18n Resource/Message 两份普通单表 XML 已删除。架构测试使用精确文件白名单阻止重新增加。

## 3. 项目级规范与门禁

持久化规范已改为 **MyBatis-Plus 优先**：

1. 普通 CRUD、单表过滤、计数、固定排序和分页必须优先使用 `MomBaseMapper`、Entity 和 Lambda Wrapper；
2. MyBatis-Plus 已能清晰表达的能力禁止新增 XML 或注解 SQL；
3. 只有 JSONB、CTE、窗口函数、复杂聚合、批量 Upsert、`SKIP LOCKED` 等数据库特性才允许自定义 SQL；
4. XML 必须说明为什么不能使用 MyBatis-Plus；
5. 正式 bounded context 继续禁止直接使用 Spring JDBC/java.sql，精确历史例外不扩大；
6. Java/XML SQL 门禁继续阻断 `${}`、`SELECT *` 和未登记技术栈旁路。

## 4. 不变边界

- 不修改 V3 或任何已发布 Flyway Migration；
- 不修改 Dynamic I18n HTTP 路径、Request/Response、权限 Code、ETag/304、400/404/409 语义；
- 不修改 Draft、Publish、Rollback、fallback、Placeholder、checksum 或双 Locale 完整版本规则；
- 不修改 IAM Schema、Parameter/Dictionary 数据模型、mom-web、mom-mobile；
- 不引入 Redis/Caffeine Cache、MQ、Outbox/Inbox、Seata、Feign 或第二 DataSource；
- 不进入 S16 Preference 或 S17 Catalog/Menu。
