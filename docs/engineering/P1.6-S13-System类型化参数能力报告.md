## 1. 本地执行方式与范围

本 Slice 只读取和修改当前本地 `mom-platform` 工作区，未执行 Fetch、Pull、Push、Rebase、Merge、Reset、GitHub Connector、GitHub CLI 或远程 API，也未检查或更新 PR #33。工具链使用本机 JDK 25.0.1 与 Maven 3.9.16。

S13 只交付 GLOBAL/APPLICATION 类型化非敏感参数；不实现 Dictionary、Preference、Locale/Timezone/Theme 持久化、Application Catalog、Menu、Navigation、Dynamic I18n、Audit Projection、Secret 管理、配置中心替代、跨服务推送、Redis 参数缓存、MQ 广播或 IAM 数据迁移。

## 2. 领域模型

`SystemParameter` 是不可变领域聚合，包含：

```text
id / scopeType / scopeCode / parameterKey / valueType / parameterValue
enabled / version / description
createdBy / createdAt / updatedBy / updatedAt
```

Java 技术主键使用 `String`，数据库使用 `varchar(19)`，由 `mom-data` 的 `ASSIGN_ID` 生成。聚合不包含 deleted、secret、sensitive、encrypted、cipherText、maskValue 等字段；S13 不提供物理删除或逻辑删除接口，只通过版本化 `enabled` 管理状态。

## 3. Scope 与 applicationCode

- `GLOBAL`：`scopeCode` 规范为非 null 空字符串，同 Key 最多一条。
- `APPLICATION`：`scopeCode` 是 System 独立稳定 `applicationCode` Reference，不访问 Application Catalog 或 IAM OAuth Client。
- 仓库不存在可复用的 System applicationCode 权威格式，因此采用小写 kebab-case、2～64 字符、`[a-z][a-z0-9-]{1,63}`；输入规范化为小写。
- IAM 既有大写 `ApplicationCode` 属于用户应用授权和 Client Policy，不复用、不映射为 System applicationCode。

## 4. Value Type 与规范化

S13 只支持：

| 类型 | 规范化 |
|---|---|
| STRING | 保留有意义普通空格；拒绝空串、全空白、控制字符；最大 4096 字符 |
| INTEGER | `BigInteger` 校验并输出规范十进制；`00012`、`+12` 均为 `12` |
| DECIMAL | `BigDecimal`、`stripTrailingZeros`、`toPlainString`；`12.5000` 为 `12.5`，`1E+3` 为 `1000` |
| BOOLEAN | 只接受并存储 `true`/`false`，拒绝大小写变体、1/0、yes/no、on/off |
| JSON | 使用 Spring Boot 4.1 管理的 Jackson 3 `ObjectMapper`；合法 JSON 压缩为紧凑字符串，最大 16384 字符 |

所有类型最终存储非空规范字符串，不执行 JSON Schema、脚本、表达式或任意 Java Object 反序列化。跨服务契约保持 `valueType + parameterValue`。

## 5. Parameter Key 与 Secret 禁止策略

Parameter Key 规范为小写、1～128 字符，格式为 `[a-z][a-z0-9]*(?:[._-][a-z0-9]+)*`，所有读写使用规范键精确匹配。

规则按大小写不敏感 Key Segment 拒绝 password、passwd、pwd、secret、token、credential、private-key/private_key/privatekey、client-secret/client_secret/clientsecret、access-key/access_key/accesskey、api-key/api_key/apikey。稳定错误为：

```text
System Parameter 不允许保存 Secret 或 Credential
```

不扫描值来推断是否为 Secret。安全边界由领域语义、Key 规则、API 无敏感字段、数据库注释、单元测试与 Review 门禁共同保证。System Parameter 不是 Credential Store、Secret Store、IAM 配置副本、OAuth Client 配置中心或 Nacos 替代品。

## 6. 数据库 Schema、表与约束

Flyway V1 独立创建 `mom_system.system_parameter`。Schema 由 `create-schemas/default-schema/schemas=mom_system` 管理，连接固定 UTC、PgJDBC TCP Keepalive 与 `ApplicationName=mom-system-server`，Hikari 基线为 1/5/3000ms/2000ms。

数据库约束包括：

1. `varchar(19)` 主键；
2. `(scope_type, scope_code, parameter_key)` 唯一约束；
3. Scope 只允许 GLOBAL/APPLICATION；
4. GLOBAL 空 code、APPLICATION kebab-case 非空 code；
5. Key 格式 Check；
6. Value Type 五值 Check；
7. parameterValue 非空；
8. enabled、version、审计字段非空；
9. version 非负；
10. 有效值解析索引。

Migration 不插入示例数据，不操作 IAM/MDM Migration，不创建数据库 ENUM、跨 Schema FK、JOIN 或动态 SQL。

## 7. MyBatis、审计与乐观锁

`SystemParameterEntity` 位于 Infrastructure，继承 `BaseAuditEntity` 并独立声明 `@Version`，不继承带逻辑删除的 `BaseEntity`。Mapper 继承 `MomBaseMapper`；普通写使用 Entity 路径触发统一审计与既有 `OptimisticLockerInnerInterceptor`，没有 `IService`、`ServiceImpl`、JdbcTemplate/JdbcClient 或第二套 MyBatis Plugin 配置。

createdBy/updatedBy 只来自 `SecurityCurrentActorProvider` 和 `mom-data` MetaObjectHandler。Web Request 与 Application Command 不包含客户端审计字段，生产实现没有硬编码 Actor。

更新与启停都携带 Version；`updateById` 受乐观锁保护，affected rows 为零转换为 `stale_version` 409，不静默覆盖或使用悲观行锁处理普通更新。

## 8. 事务与并发

创建、更新、启停均使用 System 单 DataSource 的 Spring 本地事务，不引入 Seata。类型一致性检查和写入处于同一事务；同 parameterKey 写事务通过参数化 `pg_advisory_xact_lock(hashtextextended(key, 0))` 串行化，事务结束自动释放。

同 Scope/同 Key 并发仍由数据库唯一约束最终兜底；Infrastructure 将其脱敏转换为统一 Conflict。该设计覆盖“GLOBAL 与 APPLICATION 并发创建不同类型”以及“两个相同 Scope 请求并发创建”的不同竞争面。

## 9. 类型一致性与有效值解析

创建 APPLICATION 时校验既有 GLOBAL，创建 GLOBAL 时校验全部 APPLICATION；更新 Value Type 时校验排除自身的所有 Scope。enabled 不参与一致性判断，因此不能先禁用再改变为冲突类型。

解析输入为 `parameterKey + optional applicationCode`：

```text
enabled APPLICATION → APPLICATION
否则 enabled GLOBAL → GLOBAL
否则 → 404 not_found
```

返回 `parameterKey/valueType/parameterValue/resolvedScopeType/resolvedScopeCode/version/updatedAt`。禁用 APPLICATION 不阻断 GLOBAL 回退。

## 10. HTTP API

管理 API：

```text
POST  /api/system/admin/parameters
PUT   /api/system/admin/parameters/{id}
PATCH /api/system/admin/parameters/{id}/status
GET   /api/system/admin/parameters/{id}
GET   /api/system/admin/parameters
```

分页只支持 scopeType、scopeCode、parameterKey、enabled、page、size，Key 精确匹配、固定排序、size 1～100，不接受任意字段或排序。

有效值 API：

```text
GET /api/system/parameters/{parameterKey}?applicationCode=...
```

没有 DELETE、匿名批量下载或通用成功信封。稳定业务错误为 `{code,message}`；OAuth2/OIDC 和 Spring Security 错误不由业务 Advice 改写。

## 11. 安全接入与 Permission Reference

System 复用 `mom-security` JWT Resource Server、W3C/IAM Claim Authority 转换和 revoked sid 检查，不自行解析 Token：

- `system:parameter:read`：单条、分页和有效值读取；
- `system:parameter:write`：创建、更新和启停。

所有 Parameter HTTP API 均需认证，没有 permitAll。Permission Code 仅是 IAM 权威 Reference；System Schema 不保存 Permission、Role、授权关系、Session、Refresh、Credential 或 OAuth Client。`mom-security` 传递的 Redis 只用于安全撤销检查，Parameter Domain 不依赖 Redis。

## 12. API 与 Client 决策

`mom-system-api` 新增两个枚举和有效值只读 DTO，不暴露 Entity、Mapper、Repository、Controller 或 Web Request。

`mom-system-client` 暂不创建 `SystemParameterClient`：当前仓库没有真实调用方，现有 Client 规范不要求提前发布无消费者 Feign 接口。后续真实调用方必须只暴露有效值读取，明确网络失败，不允许 Fallback 伪装默认值或 Not Found。

## 13. 缓存边界

S13 不创建 Redis Adapter、Cache Service 或参数缓存。PostgreSQL 是唯一权威。未来缓存只能是可丢弃、可重建 Projection：Key 必须包含 Scope/Code/Key，提交后才能失效，不参与权限判断、不保存 Secret，缓存异常不得修改数据库写入结果。

## 14. POM 与 ArchUnit 门禁演进

S12 空骨架门禁演进为 S13 精确白名单：Server 只允许 System API、WebMVC、Security、Data、Tracing/Metrics、Nacos、Lombok 与测试依赖；API 只允许三个 S13 契约文件；Client 仍只依赖自身 API 与 OpenFeign。`mom-iam-server` 与 `mom-mdm-api` 两个负例使用同一校验器证明违规依赖失败。

ArchUnit 继续验证 Domain、Application、Web、Infrastructure、公开 API、Client/Server 方向，并新增：Parameter Domain 无 Spring/MyBatis，Controller 不依赖 Domain/Infrastructure，System 不定义 IAM 对象或 S14+ 类型。MyBatis Entity/Mapper 的 Infrastructure 位置和 MomBaseMapper 继承由通用门禁验证。
