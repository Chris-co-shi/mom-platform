## 2. ADR 与事务边界

ADR-031 冻结以下事务模型：

```text
非事务 Catalog Publish Orchestrator
→ 构建候选 Snapshot 与 Permission Set
→ 事务外调用 IAM 批量验证
→ Transactional Commit Service
→ 事务内重新读取 Draft/Version/Checksum/Permission Set
→ Release + Published Pointer + Outbox 原子提交
```

约束：

- IAM Feign Adapter 使用 `Propagation.NEVER`；
- Redis 和 RocketMQ 不进入 System PostgreSQL 本地事务；
- 不使用 `@GlobalTransactional`；
- System Server 不新增 `mom-seata` 生产依赖；
- 远程校验成功后若 Draft 或聚合版本变化，提交阶段返回 409，不发布陈旧 Snapshot；
- Release、发布指针或 Outbox 任一写入失败，整个本地事务回滚。

## 3. IAM Permission Reference 权威能力

### 3.1 契约

IAM 新增服务间只读 API：

```http
POST /api/iam/internal/permission-references/validate
```

请求最多 1000 个规范化 Permission Code，响应只返回：

- `ENABLED`；
- `DISABLED`；
- `UNKNOWN`。

响应不暴露 Permission ID、Role、Assignment、User 或数据库审计字段。

### 3.2 分层

```text
IAM API Contract
→ IAM Client Feign Contract
→ Web Internal Controller
→ Application Service
→ Query Port
← MyBatis Query Adapter
```

内部 Controller 的装配已由显式 AutoConfiguration 管理，避免组件扫描时 `@ConditionalOnBean` 早判定导致端点缺失。

### 3.3 服务身份

System 调用 IAM 使用：

```text
grant_type = client_credentials
scope = iam.permission-reference.read
client_id = mom-system-server
```

Client Secret 只从环境 Secret 注入，不写入 Git、普通 Nacos 配置、日志或错误响应。服务 Token 不签发 Refresh Token，不透传用户 Bearer Token。

## 4. Catalog 发布期校验与对账

### 4.1 同步发布校验

Publish/Rollback 在本地事务外调用 IAM：

- 所有 Permission Reference 必须得到完整一一对应的结果；
- `UNKNOWN` 或 `DISABLED` 返回 409 `invalid_permission_reference`；
- IAM 超时/不可用返回 503 `permission_authority_unavailable`；
- IAM 协议非法或拒绝返回 502 `permission_authority_protocol_error`；
- 不允许 fallback 为“全部有效”。

### 4.2 定期对账

System 对当前已发布 Catalog 的 Permission Reference 每 10 分钟执行一次只读对账：

- 最多 1000 Code 分批；
- 记录 enabled / disabled / unknown 低基数指标；
- 仅输出不含具体 Code 的脱敏告警；
- 不自动修改 Draft、Release 或发布指针；
- Runtime 继续根据当前 JWT Authority 精确匹配并 Fail Closed。

`run-on-startup` 是默认关闭的确定性验收门禁，只在 packaged smoke 显式启用；生产仍使用定时对账。

## 5. Runtime Cache

PostgreSQL 继续是唯一权威。S18 缓存矩阵：

| 能力 | Cache 内容 | 权威确认 | 故障语义 |
|---|---|---|---|
| Catalog | 不可变发布 Snapshot | 先读 Application Header、enabled 和 publishedVersion | Redis 故障回源 PostgreSQL；数据库故障不返回旧 Cache |
| Dynamic I18n | 单 Locale 不可变 Release Snapshot | 先读 Resource Header、enabled、releaseVersion、checksum | Cache 内容损坏或不匹配时回源；数据库故障 Fail Closed |
| Parameter | 有效解析结果 | 使用稳定 Key、Scope 与 Version | Redis 故障回源 PostgreSQL |
| Dictionary | Active List / Resolve Result | 先读 Dictionary Header、enabled 与 Version | Redis 故障回源 PostgreSQL |
| User Preference | **不缓存** | PostgreSQL | ADR-031 明确排除，不是遗漏 |
| IAM Permission Validation | **不缓存** | IAM 实时权威 | 不复制 IAM 状态 |
| `/catalog/me` 最终过滤结果 | **不缓存** | 当前 JWT Authority | 避免用户授权结果陈旧 |

Cache Key 包含环境、能力、契约版本和稳定业务 Code；Value 使用显式版本 JSON，不使用 Java 原生序列化；TTL 带抖动。

## 6. 变更事件与一致性

S18 使用既有 `EventEnvelope`、Outbox、Spring Cloud Stream 与 RocketMQ：

- `system.catalog.published`；
- `system.catalog.status-changed`；
- `system.i18n.published`；
- `system.i18n.status-changed`；
- `system.parameter.changed`；
- `system.dictionary.changed`。

事件 Payload 只包含稳定 Code、版本、checksum、状态和 changeKind，不包含参数值、翻译正文、字典 Label、用户 ID、Token 或 Secret。

写侧采用真实 Application Service：

- Catalog Status 使用 `SystemCatalogRuntimeApplicationService`；
- Dictionary CRUD/Status 使用 `SystemDictionaryRuntimeApplicationService`；
- I18n Publish/Rollback/Status 使用 `SystemI18nRuntimeApplicationService`；
- Parameter CRUD/Status 在原 Application Service 中追加事件。

业务变更与 Outbox INSERT 同一 PostgreSQL 本地事务；Broker 发送在事务外。System 自消费后通过 Inbox 唯一身份去重并执行 Cache Evict。

## 8. 故障与降级

| 故障 | 行为 |
|---|---|
| IAM 不可用 | Publish/Rollback 503；定时对账失败不影响 System Readiness |
| Redis 不可用 | Runtime 回源 PostgreSQL；不把 Cache 故障冒充业务事实 |
| PostgreSQL 不可用 | 返回 503/异常，不仅凭 Redis 返回 stale 数据 |
| RocketMQ 不可用 | 业务事实与 Outbox 正常提交；Publisher 进入 RETRY，恢复后补发 |
| 重复消息 | Inbox 幂等，消费身份不重复 |
| 毒消息 | 重试耗尽进入 DLQ，不无限阻塞正常消费 |
| Cache Evict 失败 | 不反向回滚已提交数据库事务，由事件重试与 TTL 最终修复 |

