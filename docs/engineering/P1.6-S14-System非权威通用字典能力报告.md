## 3. Dictionary 适用与禁止边界

System Dictionary 只承载低频变化、无独立业务生命周期、无关系模型、不参与事务决策或权限判断的选择项、
fallback Label 与兼容 Code Reference。以下对象禁止复制：IAM User/Role/Permission/Factory Scope/Party
Binding/OAuth Client/Session/Refresh/Credential/Token；MDM Factory/Organization/Department/Person/Employee/
Party/Supplier/Customer/Material/Product/Unit/Contact；WMS Warehouse/Location/Bin/Inventory/Batch/Container；
EAM Equipment/Machine/Asset；以及生产、质量、审批、采购、销售、信用和价格状态。

领域模型没有 metadata、JSON attributes、parentId/treePath、icon/color/cssClass、locale/labelMap、Alias、
permissionCode 或 defaultValue。出现状态机、父子关系、有效期、审批、价格、单位换算、库存/生产/质检语义
或额外任意属性时，必须使用对应权威领域模型。

## 4. Domain Model、Code 与 Label

`SystemDictionary`：

```text
id / dictionaryCode / dictionaryName / enabled / version / description
createdBy / createdAt / updatedBy / updatedAt
```

`SystemDictionaryItem`：

```text
id / dictionaryId / itemCode / itemLabel / sortOrder / enabled / version / description
createdBy / createdAt / updatedBy / updatedAt
```

- dictionaryCode：3～128，小写点分段，`[a-z][a-z0-9-]*(?:\.[a-z][a-z0-9-]*)+`，全局唯一。
- itemCode：1～64，小写，`[a-z][a-z0-9_-]{0,63}`，在字典内唯一。
- 两类 Code 创建后不可修改；没有 Rename 或 Alias API。
- dictionaryName/itemLabel 是最多 200 字符的单一 fallback 文本，拒绝空白和控制字符，可版本化修改。
- Label、数据库 ID、sortOrder 都不是跨服务 Reference；Consumer 只保存 dictionaryCode + itemCode。
- S14 不创建 Locale、Translation、Message Key 或 JSON 多语言；Dynamic I18n 仍属于 S15。

## 5. Disabled Compatibility

- Dictionary 禁用不级联修改 Item enabled；Active List 直接返回空列表。
- Item 禁用后不进入 Active List，但历史兼容读取仍返回。
- 单项兼容读取不按 enabled 过滤，返回 dictionaryCode、itemCode、itemLabel、dictionaryEnabled、
  itemEnabled、effectiveEnabled、version、updatedAt。
- `effectiveEnabled = dictionaryEnabled && itemEnabled`。
- Active List 仅返回两级均启用的条目，固定按 sortOrder、itemCode、内部 ID 排序。
- 不提供物理删除或逻辑删除 API，禁用记录永久保留稳定 Code。

## 6. Database、事务、审计与并发

V2 `db/migration/system/V2__create_system_dictionary.sql` 在 `mom_system` 新增：

```text
system_dictionary
system_dictionary_item
```

两表技术主键均为 `varchar(19)` / Java `String` / MyBatis-Plus `ASSIGN_ID`。V2 包含全局/父内唯一约束、
Code/Label/sortOrder/version Check、审计非空、Active List 索引、表列注释，以及同 Schema
`dictionary_id → system_dictionary.id ON DELETE RESTRICT`。没有 PostgreSQL ENUM、示例业务数据、IAM
Permission、Cascade Delete 或跨 Schema FK/JOIN。

Entity 仅位于 Infrastructure，继承 `BaseAuditEntity` 并独立声明 `@Version`；没有逻辑删除。创建、更新、
启停由 Application 公共方法定义单 PostgreSQL 本地事务，affected rows 为 0 转换为 409。唯一冲突由数据库
最终兜底并脱敏转换为 409。没有 Advisory Lock、Seata、MQ、Outbox 或 Inbox。

createdBy/createdAt/updatedBy/updatedAt 继续由 Security CurrentActor 和 `mom-data` 统一填充，Request/
Command 不接受 createdBy、updatedBy 或 operator。

## 7. HTTP API 与 Security

管理 API：

```text
POST  /api/system/admin/dictionaries
PUT   /api/system/admin/dictionaries/{id}
PATCH /api/system/admin/dictionaries/{id}/status
GET   /api/system/admin/dictionaries/{id}
GET   /api/system/admin/dictionaries

POST  /api/system/admin/dictionaries/{dictionaryId}/items
PUT   /api/system/admin/dictionaries/{dictionaryId}/items/{itemId}
PATCH /api/system/admin/dictionaries/{dictionaryId}/items/{itemId}/status
GET   /api/system/admin/dictionaries/{dictionaryId}/items/{itemId}
GET   /api/system/admin/dictionaries/{dictionaryId}/items
```

Consumer Read API：

```text
GET /api/system/dictionaries/{dictionaryCode}/items
GET /api/system/dictionaries/{dictionaryCode}/items/{itemCode}
```

没有 DELETE、匿名读取、全库导出、Label 模糊搜索、任意排序、Tree 或 Metadata API。全部端点复用 S13
Resource Server、IAM Claim Authority 与 revoked sid：`system:dictionary:read` 保护管理查询和 Consumer
读取，`system:dictionary:write` 保护创建、更新和启停。Permission Code 只是 IAM Reference；System 不保存
Permission、Role 或授权关系。

## 8. API、Client 与 Cache 决策

`mom-system-api` 新增 `SystemDictionaryItemOption` 和 `ResolvedSystemDictionaryItem`，不暴露 Entity、Mapper、
Repository、Web Request、数据库 ID 或 MyBatis 类型。

仓库内没有真实跨服务调用方，因此 `mom-system-client` 保持空调用骨架，不创建提前设计的 Feign Client。
网络失败不能被未来 Client 伪装成 Not Found 或默认 Label。

S14 不实现 Redis/Caffeine Dictionary Cache、Cache Eviction、MQ、Change Event、Long Poll 或 Config Push。
PostgreSQL 是唯一权威；未来 Cache 只能是事务提交后失效、可丢弃和可重建的 Projection。

## 9. POM 与 ArchUnit 门禁

Server 直接依赖白名单不变。API 文件白名单精确增加两个字典只读契约；`mom-iam-server` 与
`mom-mdm-api` 负例继续证明 IAM Server 和未经批准业务 API 依赖会失败。资源白名单精确登记 V1/V2 与三个
Mapper XML，没有放宽为通配业务依赖。

ArchUnit 新增 Dictionary Domain 无 Spring/MyBatis、Controller 只进入 Dictionary Application、Parameter/
Dictionary 子域不互相穿透实现层，并继续由通用规则验证 Application 无 Mapper/Entity、Entity/Mapper 只在
Infrastructure、API/Client/Server 方向和 IAM 内部实现禁区。System 仍禁止定义 Factory、Warehouse、
Equipment、Person、Party、Preference、Catalog、Menu、Navigation 等对象。
