## 2. 原始问题

S09 已把原单体 Admin Service 拆为多个用例服务，但生产实现仍集中在：

```text
io.github.chrisshi.mom.iam.admin
```

该包同时包含：

- Controller 与 HTTP Command；
- Application Service；
- Spring Configuration；
- 错误模型；
- 审计事件构造；
- Session 撤销编排；
- 最后管理员保护；
- 直接依赖 Infrastructure Repository 的事务脚本。

User、Role 与授权关系虽然拥有明确数据表和版本边界，但状态迁移、不变量和资格判断主要散落在 Application 条件分支中。该结构不满足 ADR-027 与 ADR-028 已冻结的：

```text
Web → Application → Domain Port ← Infrastructure Adapter
```

## 3. 分层整改

### 3.1 删除混合 Package

正式生产代码已退出旧 `io.github.chrisshi.mom.iam.admin` 包，不保留代理类或兼容 Facade。

最终职责归位：

```text
web.admin
    Controller、HTTP DTO、错误响应、请求上下文和 JWT Actor 适配

application.admin
    用例服务、Command、View、Actor、审计与 Session 撤销编排

application.admin.port
    Query、关系写入、密码摘要、ID、外部校验与安全审计 Outbound Port

domain.user / domain.role / domain.authorization / domain.policy
    聚合、状态行为、版本规则与跨聚合策略

infrastructure.persistence
    MyBatis Repository Adapter、关系 Adapter 与 Query Adapter

configuration
    Spring Bean 装配
```

已删除无独立业务价值的：

- `IamAdminService`；
- `IamAdminOperationSupport`；
- 旧单体 `IamAdminController`；
- 旧 Admin Configuration；
- 旧 Admin User/Role/Client Repository 类型。

### 3.2 Controller 按资源拆分

原单体 Controller 拆为：

- `IamUserAdminController`；
- `IamRoleAdminController`；
- `IamSessionAdminController`；
- `IamClientAdminController`；
- `IamSecurityAuditController`。

拆分后仍由聚合契约测试锁定全部 25 条已发布 HTTP Method/Path、请求字段和响应状态。

### 3.3 Application 只依赖 Port

`application.admin` 不再接收或依赖：

- `Authentication`；
- `HttpServletRequest`；
- Servlet DTO；
- Mapper；
- Persistence Entity；
- 具体 MyBatis Repository Adapter；
- Spring Web 与 Spring Security 入站类型。

Web Adapter 将已验证的 `MomJwtAuthorization` 转换为 `IamAdminActor`；Application 继续在 Actor 边界校验 Permission，保证非 Controller 调用路径不能绕过授权。

## 4. 领域模型

### 4.1 `IamUserAccount`

承载：

- User 聚合版本校验；
- 禁止禁用当前账号；
- 禁止删除当前账号；
- 管理员不得通过管理接口重置自己；
- 状态变更决策；
- Party Binding 资格；
- Mobile Access 资格。

### 4.2 `IamRole`

承载：

- Role 聚合版本校验；
- 内置角色不可修改；
- 内置角色 Permission 不可替换；
- 禁用角色不可分配；
- 用户类型与角色适用类型匹配；
- `PLATFORM_ADMIN` 固定不变量。

### 4.3 `IamUserAuthorization`

统一承载：

- User Version 并发边界；
- Role Assignment；
- Factory Scope；
- Mobile Access；
- Party Binding；
- 禁用 Mobile Access 与 Party 重绑时的 Session 撤销决策。

### 4.4 最后管理员策略

原先隐藏在 God Support 中的最后管理员保护已形成：

```text
PlatformAdministratorRetentionPolicy
```

Application 负责取得锁定后的事实，Domain Policy 负责裁决是否允许降低有效平台管理员数量。数据库行锁、重新计数和 Fail Closed 语义保持不变。

## 5. Repository 与 Query Adapter

### 5.1 User 与 Role 单表 Adapter

两个明确单表 Aggregate Adapter 已迁移为：

```java
MybatisIamUserAccountRepository
    extends CrudRepository<IamUserMapper, IamUserEntity>
    implements IamUserAccountRepository

MybatisIamRoleRepository
    extends CrudRepository<IamRoleMapper, IamRoleEntity>
    implements IamRoleRepository
```

Application 只依赖 Domain Repository Port，不依赖具体 Adapter。

### 5.2 精确保留专用 Adapter

以下场景没有为了形式统一机械继承单一 `CrudRepository`：

- Authorization Assignment；
- User Access；
- Authorization Read Model；
- Session Admin Query；
- Permission Query；
- Security Audit Query；
- OAuth Client Policy；
- Session/Refresh 协议状态存储。

这些能力属于多 Mapper、多表关系、Projection、追加写或协议状态机，继续使用专用 Port/Adapter。

## 7. 自动门禁

### 7.1 ArchUnit

新增 `IamAdminLayerArchitectureTest`，阻断：

- `application.admin` 依赖 Infrastructure；
- `application.admin` 依赖 Web、Servlet、Spring Web 或 Spring Security；
- `web.admin` 直接依赖 Infrastructure；
- 旧 `io.github.chrisshi.mom.iam.admin` 包重新出现生产类型；
- User/Role Adapter 不继承 Spring `CrudRepository`；
- User/Role Adapter 不实现对应 Domain Repository Port。

### 7.2 Java Persistence Baseline

IAM User/Role Adapter 已加入必需 `CrudRepository` 清单，继续阻断：

- `IService/ServiceImpl`；
- Domain/Application 暴露 `IRepository`；
- MyBatis-Plus Repository 越过 Infrastructure；
- 上层导入具体 `Mybatis*Repository`；
- 单表 Adapter 退回重复直接 Mapper CRUD。
