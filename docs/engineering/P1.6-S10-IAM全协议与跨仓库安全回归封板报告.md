## 4. PC 三应用

三个应用都使用 `packages/first-party-auth`，没有把 `packages/auth` 的标准 PKCE Runtime 初始化为生产 PC Runtime。第一方 Runtime 固定调用 `/api/iam/auth/login`、`/api/iam/auth/refresh`、`/api/iam/auth/logout` 和 `/api/iam/me`；Token 位于当前 Tab 的 `sessionStorage`，密码不持久化。

本次 mom-web `pnpm run check` 通过 29 项认证/安全测试、2 项 Admin Runtime 测试和 7 项 UI 回归；三个应用类型检查和生产构建通过。已有测试证明 Single Flight Refresh、401 只重试一次、403 不触发 Token Refresh、高风险写请求不会静默重放、Logout 即使 IAM 不可用也会清理本地状态。

局限：这些是固定 Ref 的 L1/L2/L5 客户端证据，不是三个真实账号连接 IAM、Gateway、PostgreSQL 和 Redis 的 L4 E2E。因此三个 PC 应用整体状态为 `Partial`，不是完整封板 `Passed`。

## 5. Mobile PKCE/OIDC 与 EG-01

固定 Ref 源码确认：

1. 使用系统浏览器发起 `response_type=code`；
2. 生成 PKCE S256、`state`、`nonce` 和一次性 verifier；
3. 回调精确校验 protocol、host、path 和 state；
4. 标准 Token Endpoint 使用 `authorization_code`/`refresh_token` 与 snake_case 字段；
5. ID Token 校验 JWK、`kid`、Issuer、Audience、Nonce、时间和 RS256；
6. Access Token 只在运行时内存；Refresh Token 使用 Lease/Replacement 抽象，结果不确定时 Fail Closed；
7. 业务 Bearer 只允许同源 Gateway `/api/**`。

认证 Runtime 8 项测试通过，H5 构建通过。但 `MobileAuthRuntime.logout()` 只执行本地清理，不调用现有 `POST /api/iam/auth/logout`，无法证明服务端 Session、Refresh 和 revoked sid 已撤销。现有平台 Logout 已可使用 Bearer 精确撤销当前 sid，但接线必须修改只读 mom-mobile；用户没有指定可写分支和 PR，因此 S10 不得擅自修改。

**EG-01：Open / Blocking。** 建议在 mom-mobile 指定分支中，让 Logout 先以当前 Bearer 调用现有服务端能力；成功或网络结果不确定后均清理本地状态，不新增 API、不改变 OIDC 登录协议。回滚为恢复当前本地清理实现。完成前不得写成 Mobile 服务端 Logout Passed。

mom-mobile 完整 `pnpm run check` 还被既有 `src/offline/service.test.ts` 的 `@/auth` Vitest 别名解析失败阻断；只读边界下未修改测试配置。

## 7. Gateway 与 Resource Server（EG-02）

Gateway 既有实现保持不变：独立验证 JWT/JWK/Issuer/Audience，清理客户端 `X-MOM-*`，校验 Client 路由和 revoked sid；Redis 失败返回 503，健康路径不依赖撤销 Store，Bearer 原样转发。

由于 mom-infra 不可用，不能以不可直连部署证据关闭 EG-02。本次采用路径 B，在共享 Servlet Resource Server 增加：

- `MomRevokedSessionChecker`：协议中立只读端口；
- `RedisMomRevokedSessionChecker`：Infrastructure Adapter，复用应用唯一 Redis 和 IAM 现有 Key 前缀；
- `MomRevokedSessionFilter`：在 `BearerTokenAuthenticationFilter` 后读取已验证 JWT 的 sid；
- active sid 放行；revoked/缺少 sid 返回 Bearer 401；Redis 超时、连接失败或不确定结果返回 503；
- `/actuator/health/**`、`/actuator/info`、`/error` 等配置公开路径跳过撤销检查；
- 不读取 Gateway Header，不调用 IAM HTTP，不写 Redis，不改变 TTL、JWT 或 Session 撤销事务。

组件测试验证业务服务直连、active/revoked/missing sid、503、公开路径和伪造 Header；Redis 单元测试验证超时/不确定结果；真实 Redis IT 验证 active/revoked 和连接不可用。Gateway 的 Issuer/Audience/Client/撤销/Header 测试与共享 JWT validator 测试继续通过。

**EG-02：Closed at platform implementation/test boundary。** 关闭依据是路径 B，不依赖缺失的部署证据；S10 总体仍因 EG-01、EG-03 和高层级证据阻塞。
