## 2. 审计方法

审计不以关键词匹配数量作为结论，而是逐项检查三层证据：

1. **依赖和资源**：依赖、静态 locale 文件、`MessageSource`、配置、API 类型。
2. **初始化和调用链**：依赖是否进入生产入口、资源加载来源、是否到达生产页面/服务、是否存在远程 HTTP 请求。
3. **业务生命周期**：谁编辑、谁发布、谁消费、如何版本化和回退、是否确实要求客户端不重新构建即可更新。

对只读仓库使用已抓取的远程 Ref 直接执行 `git ls-tree`、`git show` 和 `git grep`，没有使用或修改工作区未提交内容。对搜索结果逐项查看初始化代码、API Client、页面/菜单入口、Store、Backlog 和运行时边界。

## 5. mom-platform 审计结论

`mom-system-platform` 当前只实现 S13 Parameter 与 S14 Dictionary。数据库只有 V1/V2 Migration；未发现 V3、翻译表、Locale 列、翻译 API、Controller、Client、缓存、页面或 Permission Code。现有 POM/ArchUnit 门禁已经禁止 `DynamicI18n` 等后续能力提前进入 System，无需为本次纯文档审计增加测试。

IAM、Framework、Gateway 和各服务存在中文或英文固定异常消息，但这些消息随服务构建发布，没有管理员编辑、发布、回滚或客户端资源版本。它们属于 `Server Fixed Message`，不证明 Dynamic I18n 调用方。

未发现生产 `MessageSource`、`ResourceBundle` 或 `messages*.properties`。即使未来某服务增加静态 ResourceBundle，也仍应由该服务 Own，除非另有真实远程动态调用链。

## 6. mom-web 审计结论

Web 的完整生产调用链为：

```text
源码 zh-CN/en-US JSON
→ import.meta.glob
→ setupI18n / loadLocaleMessages
→ Vue I18n $t / route titleKey
→ MOM Admin 页面、菜单和页签
```

`loadMessages` 是应用注入的本地异步模块加载函数，不是 HTTP Client。`setLocaleMessage` 与 `mergeLocaleMessage` 操作的是构建产物中的资源。语言切换只更新本地 Preference 并加载另一组内置资源。API Client 和生产页面均没有翻译资源远程请求，也没有创建、修改、发布、回滚或版本管理页面。

因此 Web 是静态国际化的真实消费者，但不是 Dynamic I18n 的真实调用方。静态 `zh-CN/en-US` 资源继续由 mom-web Own。

## 7. mom-mobile 审计结论

Mobile `package.json` 声明 `vue-i18n`，但 `src/main.ts` 只注册 Pinia，未创建或注册 I18n；仓库树没有 `src/locales` 或消息资源，API Client 也没有翻译资源请求。依赖存在只代表框架能力，不能证明调用方。

Mobile 后续应先完成客户端静态 `zh-CN/en-US` 基础能力。它不构成当前 System Dynamic I18n 的进入理由。

## 8. 静态翻译与动态翻译

| 维度 | 静态翻译 | Dynamic I18n |
| -- | -- | -- |
| 来源 | Git 中 JSON/TS/ResourceBundle | 运行时远程服务 |
| 变更生效 | 重新构建/发布客户端或服务 | 管理员发布后无需重新构建客户端 |
| 版本 | 应用版本/Commit | 独立资源版本 |
| 管理 | Code Review 与发布流水线 | 创建、修改、发布、回滚、审计 |
| 失败 | 构建内默认语言/Key | 静态 fallback、Locale fallback、缓存版本和服务降级 |

Vue I18n、`$t()`、`useI18n()`、`Accept-Language` 和中英文界面只能证明国际化能力，不证明远程动态生命周期。

## 9. Locale Preference 与 Dynamic I18n

Locale Preference 只回答“用户选择哪一种已支持语言”。Dynamic I18n 回答“某个 Locale 下 Key 对应的资源由谁在运行时编辑、发布和版本化”。Web 当前的语言入口只切换构建内置 `zh-CN/en-US`，属于 Preference；未来 S16 即使将 Preference 保存到 System，也不会自动产生 Dynamic I18n 调用方。

## 10. 业务多语言字段所有权

Material、Product、Factory、Equipment、Warehouse、Party、Supplier、Customer 和业务单据的多语言名称或内容属于对应权威业务域，不进入 System Dynamic I18n：

- MDM Own Material、Product、Factory、Person/Party 等主数据；
- WMS Own Warehouse、库存与批次；
- EAM Own Equipment/Asset；
- 采购/SRM 与销售/CRM 分别 Own 供应商采购关系和客户销售关系；
- IAM Own Permission、Role 和安全对象的权威数据。

System 不复制这些对象形成通用翻译表。

## 11. System Dictionary Label 边界

Dictionary Item 的 `label` 是单一、可修改的 fallback 展示文本，不是 Locale Map，不承载 `messageKey`，也不代替业务领域枚举或权威主数据。未来需要多语言 Dictionary 展示时必须先证明真实调用方和资源所有权，不能通过给 S14 表追加任意多语言 JSON 绕过 S15 门禁。

## 12. Application Catalog/Menu 文案边界

Application Catalog/Menu/Navigation 属于 S17 候选。System 未来可 Own 目录元数据和受控显示字段，Web 继续 Own 可执行路由/组件映射。当前 mom-web 菜单使用源码 `titleKey` 和本地翻译；Backlog 也优先要求后端返回稳定 `menuCode/i18nKey`、前端维护翻译。S17 候选不等于 S15 Dynamic I18n 调用方。

## 13. 动态生命周期、失败语义和管理用例

当前没有以下事实：

- 管理员/运营角色和翻译内容审核流程；
- 创建、修改、发布、回滚、版本查看或 Locale 管理用例；
- 独立资源版本、ETag 或兼容契约；
- 静态 fallback、Locale fallback、缺失 Key 和不可用处理的远程协议；
- 客户端缓存、刷新或更新生效时机；
- 无需重新构建客户端即可更新的已批准产品需求。

由于真实调用方本身不存在，本任务不为假设性能力设计这些语义。

## 14. Go 判定门禁

只有同时满足以下条件才能作出 `Go`：

1. 至少一个生产页面、组件、移动页面或服务通过远程 API 获取 `locale + key + value` 并实际渲染；
2. 管理员发布后必须无需重新构建客户端即可生效；
3. 资源明确属于 System 通用 UI 或某个应用运行时 UI，而不是业务领域数据；
4. 版本、静态/Locale fallback、缺失 Key、不可用、缓存和生效时机均可形成契约；
5. 存在真实管理角色和创建、修改、发布、回滚、版本/Locale 管理用例。

本次审计没有任何候选同时满足这些条件。

## 15. 最终决策

```text
S15：Deferred — No Real Caller
```

冻结边界：

- mom-web 继续 Own 静态翻译资源；
- mom-mobile 后续先完成静态 `zh-CN/en-US` 基础能力；
- 固定服务端消息继续由各服务按需管理；
- 业务主数据多语言字段由权威业务领域 Own；
- System 不创建 Dynamic I18n；
- 不创建数据库表、Migration、API、Client、管理页面、缓存或 Permission Code；
- 不修改 mom-web、mom-mobile、S13 Parameter 或 S14 Dictionary 生产行为。

Deferred 不是永久拒绝。

## 16. 重新启动条件

重新启动 S15 必须至少出现以下一项，并在实现前重新通过完整 Go 门禁：

1. 真实生产页面需要运行时远程翻译；
2. 明确管理员需要不发布客户端即可修改文案；
3. 已存在或已批准完整 API 调用方；
4. 已形成版本和 fallback 契约；
5. 已明确资源所有权；
6. Chris 重新批准 S15 实现。

单独满足“未来可能需要”、框架支持、TODO 或依赖存在仍不够。
