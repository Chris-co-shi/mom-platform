- Source Application/Release Version；
- JSONB Snapshot；

- SHA-256 Checksum；
- Change Note 与发布审计。

数据库 Trigger 拒绝 UPDATE/DELETE。Rollback 复制历史内容形成新版本，不修改旧 Release。

## 7. Runtime API

```text
GET /api/system/catalog/me
GET /api/system/catalog/applications/{applicationCode}
```

Runtime：

-只允许已认证用户；
-只读取不可变 Release；
- Application 禁用立即隐藏当前发布版本；
-不读取 Draft；
-不调用 IAM；
-不返回数据库 ID、Path、Component、Layout 或脚本；
-支持私有 `no-cache` 与强 ETag/304；
- Snapshot checksum 或元数据不一致时 Fail Closed。

## 8. Permission Reference

`MomJwtGrantedAuthoritiesConverter` 的真实行为：

- Role 添加 `ROLE_` 前缀；
- Permission 保留原始 `domain:resource:action`。

因此 Runtime 精确使用：

```text
Authentication Authorities.contains(permissionCode)
```

无 Permission 节点表示已认证即可见；受保护节点没有对应 Authority 时不返回；GROUP 没有可见子节点时不返回。

该过滤只控制目录展示。业务 API 仍必须独立执行 Resource Server 鉴权和对象/数据权限判断。

## 9. Dynamic I18n

Application 和 Navigation 保存 Dynamic I18n 稳定 Reference，不保存翻译值。

Publish 收集 Application 与所有节点引用，并验证目标 Resource/Message 已发布。无效引用返回 `409 invalid_i18n_reference`。

Catalog 与 I18n 没有物理 FK。Catalog 不复制 `zh-CN/en-US` 翻译列。

## 10. Publish、并发与回滚

Application Version 是 Catalog Draft 聚合并发边界。

Navigation 创建、更新、移动、启停和排序都会 Touch Application Version。节点自身同时保留 Version。

Publish：

1.校验 Application Version；
2.要求 Application enabled；
3.构建并校验完整树；
4.验证 I18n Reference；
5.生成确定性 JSON；
6.校验 1 MiB 上限；
7.计算 SHA-256；
8.拒绝 No-op；
9.追加 Release；
10. CAS 推进发布指针。

全部在 System 单 PostgreSQL 本地事务中执行，不使用 Redis Lock、Seata 或跨服务事务。

Rollback：

-验证目标历史版本；
-重新验证 Snapshot 和 I18n Reference；
-拒绝 No-op；
-复制目标内容创建新 Release Version；
-记录 `sourceReleaseVersion`；
-不改变 Draft。

## 11. IAM V10

IAM V10 注册：

- `system:catalog:read`，LOW；
- `system:catalog:write`，MEDIUM；
- `system:catalog:publish`，HIGH。

三个 Permission 均为 Built-in，并赋予已启用的内置 `PLATFORM_ADMIN`。Migration 不修改 OAuth Client、JWT Claim、Session 或 Token。

- Runtime 只接受已验证 Authentication；
-严格未知字段拒绝；

Architecture Test 已从“禁止 S17 类型”演进为“允许 Catalog Metadata，但禁止第二 IAM、主数据权威和可执行客户端 Artifact”。

## 14. Deferred

### 14.1 Permission 发布期权威验证

当前 S17 Publish 不跨服务调用 IAM 验证 `permissionCode` 是否存在或启用。原因是当前缺少稳定、批量、协议化的 IAM Permission Validation API。

当前安全语义：

-无对应 JWT Authority 时节点不返回；
-错误或已失效 Code 不扩大权限；
-属于 Fail Closed。

S18 输入：

- IAM Permission 批量验证契约；
-发布期 Fail Closed 校验；
-未知/禁用 Reference 对账；
- Permission 状态变更通知；
-陈旧 JWT 与陈旧 Catalog 收敛。

### 14.2 缓存和变更通知

S17 Runtime 直接读取 PostgreSQL 发布指针和不可变 Release。Redis/Caffeine、消息通知和失效策略进入 S18，缓存不得成为权威。

### 14.3 客户端接入

mom-web/mom-mobile 正式读取 Catalog、Route/Icon Registry、版本兼容、静态 fallback 和跨仓库 E2E 尚未实施。

### 14.4 继续禁止

- External URL；
-远程模块；
-动态 Component Path；
- JavaScript/HTML；
-客户端自报 Permission；
- System 保存 Role/Permission Assignment。
