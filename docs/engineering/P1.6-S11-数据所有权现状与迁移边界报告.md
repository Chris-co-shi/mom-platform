## 9. Projection 候选

候选包括 Factory/Party/Person 展示摘要、System Application Catalog 客户端缓存、未来跨领域 Audit 查询。所有候选必须带来源上下文、ID、版本/更新时间和投影时间，可全量重建且只读。当前没有批准任何 Projection 表。

安全授权、库存余额、设备控制和原始审计不得从陈旧 Projection 放行。普通展示可以降级为上次成功值并明确陈旧。

## 10. Preference 候选

Locale、显示时区、Theme、Density、Page Size、Default Application、Default/Last Factory、View Setting、Table Columns、Sorting、Saved Filters、Dashboard Layout、Favorites。每个 Key 必须类型化、白名单、版本化、有默认值和审计策略；不得用任意深层 JSON。

Preference 不是 Authorization。Default Factory 的使用顺序固定为 System 偏好 → IAM Scope → MDM 有效状态 → 当前请求上下文。Locale/Timezone 不进入授权 Claim；Factory Timezone 仍归 MDM；API 时间点仍为 UTC/RFC 3339。

## 11. Forbidden Copy

- Credential、密码摘要、Pepper、OAuth Client Secret、签名私钥和 Device Credential。
- Refresh Token 明文/摘要、Session 权威状态、revoked sid 权威集合。
- Role/Permission 定义、User Role、Factory Scope、Party Binding 和 JWT Claims 规则。
- Factory/Warehouse/Equipment/Supplier/Customer/Unit 等主数据被伪装成 System Dictionary。
- 客户端提交的 Role、Permission、Factory/Party Scope 被当作权威。

## 12. IAM 保留项

账号、Username、最小 Display Name、Credential、Account/Lock/First Login、User Type、Mobile Access、Role、Permission、User Role、Factory Scope、Party Binding、OAuth Client/Policy、Session、Refresh、revoked sid、Claims、Token 签发/撤销、`/api/iam/me` 和 Security Audit 全部保留。

`IamAdminService` 不迁移。它是 IAM 安全用例兼容 Facade，不包含 System 参数、字典、偏好或应用目录数据。

## 15. WMS 权威项

Warehouse、Warehouse Status、Storage Location/Bin 与 Factory-Warehouse 关系由 WMS Own。当前没有生产实现，不迁移现存数据。IAM 无真实 Warehouse 授权需求，不新增 Warehouse Scope；System 不把 Warehouse 建成字典。

## 16. EAM 权威项

Equipment Asset、Machine、台账状态、履历与 Factory/Location 资产归属由 EAM Own。业务 Device Identity/IoT Connection 归属推荐 EAM；Device Credential 属于未来 Device IAM/IoT Security。System 与当前用户 IAM 均不拥有设备主数据。

## 17. 需要迁移的真实数据

IAM 结论：**No current production migration required**。

未来真实候选只来自前端体验数据源转移：Web Locale/Timezone/Theme/currentFactory 到 System Preference，以及静态应用/菜单元数据到 System Catalog。前者当前是本地缓存，后者是源码配置，均不是 IAM 生产数据迁移。迁移必须分别在 S16/S17 设计兼容、双读或 fallback；本次不实现。

## 18. 不需要迁移的对象

Account、Credential、Display Name、User Type、Role、Permission、User Role、Factory Scope、Party Binding、Mobile Access、OAuth Client/Policy、Session、Refresh、revoked sid、JWT Claims、Security Audit、`IamAdminService` 均不迁移。`employee_no` 与 Factory/Party ID 目前是允许的 Reference，也不因 S11 改表。

## 19. 未决问题

需要 Chris 决策的七项及推荐：

1. Person/Employee：V1 推荐 MDM，出现独立 HR 生命周期后再 ADR 拆分。
2. Party/Supplier/Customer：V1 推荐 MDM 统一 Party 核心，交易关系归业务域。
3. Application Catalog：推荐独立 Application Code，可选引用 IAM Client ID。
4. Display Name：推荐 IAM 保留最小属性，不承载 Person Profile。
5. 多 Party：推荐 P1.6 保持一账号一个 Party，真实需求后另立 ADR。
6. Dynamic I18n：推荐 S15 继续条件性，无调用方则推迟。
7. Audit Projection：推荐暂缓，真实合规查询出现后再决定 System 或独立 Compliance 边界。

各项候选、兼容/实现影响与不决策后果见 ADR-025 第 23 节。

## 20. ADR-025 推荐结论

推荐方案 C：IAM 保持安全权威；System 只拥有平台参数、受限通用字典、体验偏好、应用目录/菜单；MDM 拥有 Factory/组织/人员/Party/单位；WMS 拥有 Warehouse；EAM 拥有设备台账；跨域通过 ID/Code Reference、API/事件与可重建 Projection 协作。

ADR 当前必须保持 Proposed。方案 A“全部塞入 IAM”、方案 B“System 接管 IAM Admin”、方案 D“共享数据库/跨 Schema Join”均不满足单一权威和安全边界。

## 21. S12 输入
