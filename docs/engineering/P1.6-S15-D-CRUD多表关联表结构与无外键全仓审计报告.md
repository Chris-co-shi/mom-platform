## 5. 物理外键与完整性闭环

System V5 和 IAM V9 均先在同一 Schema 对每个关系执行孤儿查询，非零即 `RAISE EXCEPTION`，然后精确 `DROP CONSTRAINT`。历史 Versioned Migration 未修改。原查询索引保留；无外键门禁同时验证历史来源与指定移除 Migration/约束名一一配对。

System 创建 Message/Item 继续由 Application 校验 Resource/Dictionary；Resource、Dictionary 和 Release 无物理删除 API，禁用不删除 Draft/Release。IAM 用户、角色、Permission、Client Policy、Session 等本地引用继续由行锁、应用校验、Unique/Check、affected rows、本地事务和状态机保护。V9 对全部 12 个 IAM 关系先做孤儿检查。

## 7. 未修复项与退出条件

### ASSOC-002：INTERNAL Factory 引用权威校验

- 风险：格式正确但不存在的 Factory ID 可进入 IAM Scope；当前只对外部用户执行 Party/Factory 关系校验。
- 暂不修复原因：仓库当前没有 MDM Factory 权威模型或批量 Query API；伪造本地表、逐条远程调用或全部拒绝非空 Scope 都会制造错误行为。
- 责任 Slice：未来 MDM Factory 权威能力与 IAM Scope 集成 Slice。
- 退出条件：MDM 发布有上限的批量 Factory 存在性 API；IAM Client 有有限超时、写请求无自动重试；Application 在同一命令写入前批量 fail-closed 校验，并新增契约/故障/PostgreSQL 测试。

### ASSOC-003：外部 Party 引用权威校验

- 风险：格式正确但不存在的 Supplier/Customer Party ID 可被绑定；后续外部 Factory 校验会失败，但创建时未闭环。
- 暂不修复原因：Supplier/Customer 业务权威域和批量 Party Query API 尚未实现；IAM 不得复制 Party 主数据或跨 Schema 查询。
- 责任 Slice：未来 Party Core 与 Supplier/Customer 关系权威集成 Slice。
- 退出条件：权威服务提供稳定批量 Query API/事件投影；创建与重绑 fail-closed，依赖不可用返回稳定错误，并覆盖事务回滚、超时和重复请求。

除上述两个缺少权威上游能力的 Deferred 项外，无可在本任务内安全修复而未修复的问题。

## 8. 回滚与后续治理

V5/V9 不回写历史 Migration。若升级前孤儿检查失败，应停止写入、按诊断 SQL 修复数据后重新迁移；不得跳过检查。应用回滚仍可在无 FK Schema 上运行，因为业务写入路径不依赖数据库 FK 成功。V6 只澄清快照兼容列，回滚应用不会破坏表结构。任何新业务表、Mapper/XML、Repository、Query 或 CRUD 都必须附三份模板之一和 PostgreSQL 证据。
